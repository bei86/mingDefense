# 灵林守阵 / mingDefense

《小妖卫道》玩法研究基础上的竖屏 H5 原型。当前完成 M0–M3 的五关可玩闭环：六种灵兽、1–6 阶、经验天赋、Boss 和本地检查点恢复。已有来源的规则继续保留，缺失数值按用户授权设计；这不是原作数值还原完成版。

## 启动

需要 Node.js 20.19+ 或 22.12+（本机验证 Node 24.12）。

```powershell
npm.cmd install
npm.cmd run dev
```

打开 http://127.0.0.1:5173/ 。默认仅监听本机。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`test` 包含规则、检查点及三条正常经济路线模拟；完整模拟结果输出到 `artifacts/campaign-balance-samples.json`。`build` 包含 TypeScript 检查与生产构建。

## 第一局与五关流程

1. 领取一只烬灵鼠，部署在第 2 列第 4 行；另一只鼠叠放上去合成 2 阶。
2. 岩甲豚放第 3 列第 4 行，横占两格；青锋隼放第 4 列第 5 行，占 2×2 格。
3. 开始守阵。灵兽自动攻击，击杀积累经验；升级会暂停并提供最多三项天赋，选择后继续。
   开场后每秒一只连续出怪，波次之间不留空档，也不等待上一波清完；本关配置出完后停止生成。
4. 按住聚灵石消耗灵气提升攻速。暂停、切出页面、失焦和升级选择都会清除按住状态；继续时重新按住。支持 1×/2× 速度。
5. 胜利后结算通关、产钱及天赋收入，进入下一关整备时免费刷新三张招募，覆盖上一关未领取的招募。阵容、格子及修行保留，下次开战全员满血。失败重试或返回布阵不会刷新招募。
6. 第 5 关首领会横扫预警，低血进入二阶段并召唤小怪；所有波次、首领、已生成小怪及已释放伤害事件结束后才胜利。

可点选后放置，也可拖动。同种同阶叠放合成，最高六阶；形状不随升阶改变。备战席最多两只且不参战。刷新花费 15 灵钱，获得三张招募；未领取内容需确认放弃。扩地令只解锁边相邻的一个格子。非法操作不会消耗招募、随机数或灵钱。准备期可撤销上一次布阵；刷新和遣散不能撤销。

新增灵兽：灵金桃存活时定期产钱，霜尾鲤减速并在三阶后周期冰冻，月音狐提供护盾、三阶攻击光环及五阶初始灵气。岩甲豚和青锋隼接入五阶技能。

敌人先清空最前方有存活灵兽的一整排，再攻击下一排；多格灵兽按最上方占格归排。同排先攻击低阶，同阶按用户指定的类型仇恨优先：桃 8 > 狐 7 > 鼠 6 > 豚 5 > 鲤 2 > 隼 1；仍相同则按距离、实例 ID。类型顺序由用户修正，等级暂按低阶优先，数字仅表示原型相对优先级 P；未查到完整原作仇恨数值表，见 `docs/research/2026-10-16-enemy-threat-and-rank.md`。选中灵兽可查看。

胜负结算可展开“逐兽战报”，查看每只上阵灵兽的实际伤害、生命承伤、桃产钱、施盾/吸收量与重伤情况；同种灵兽按位置区分。伤害不计过量部分，护盾吸收单列，失败的产钱仅供复盘、不计入保留收益。聚灵记录实际生效时间。多格灵兽以整块不透明底色遮住占格，避免误认为空格。

## 存档与重试

本地自动保存整备、关后待选天赋和完成状态。战斗中刷新、失败重试或中止会回到完整的开战检查点，本关产钱、经验和天赋全部回滚。通关奖励每关只结算一次。“重新开始”清空本轮进度。

存档键为 `ming-defense:campaign`，按 `schemaVersion` 和 `contentVersion` 验证。旧版本或损坏数据先备份再开始新局；备份失败保留原档并停止覆盖。存储不可用时仍可玩，但刷新可能丢失新进度。数据仅在当前浏览器本地保存，未实现账号和云同步。

当前内容版本为 `prototype-2026-10-16-v6`。已知 v2/v3/v4/v5 可在备份后自动迁移，保留阵容、灵钱、成长和关卡，后续新战采用当前逐排、等级、仇恨规则与连续出怪节奏；旧胜利战报保留原结果，缺少逐兽数据时提供说明。迁移备份/写入失败时原主档保留，本轮停止自动覆盖。其他未知版本仍按上述不兼容流程处理。

## 结构与校准

- `src/game/content.ts` 直接读取 `docs/superpowers/specs/2026-10-14-prototype-balance.json`，数值以该 JSON 为准，v1 快照单独保留。改数值时同步更新内容版本及对应规则说明。
- `session.ts` 管理招募、布局、合成、阶段和收益事务；商店、天赋、战斗使用独立可序列化随机状态。
- `combat.ts` / `combat-skills.ts` / `combat-model.ts` 是独立 50ms 模拟器，不依赖 React/Phaser；批量伤害支持同帧互杀先判负，死亡取消未释放攻击，已释放剑阵与鹰双段继续生效。
- `progression.ts` 处理经验、天赋条件、品质权重和上限；`persistence.ts` 验证存档并处理恢复。
- `clock.ts` 处理速度与暂停，不追补离屏时间；`render/Battlefield.tsx` 用 Phaser 绘制原创几何占位角色，`ui` 提供 DOM 操作及 HUD。
- 仅开发服务器支持 http://127.0.0.1:5173/?playtest=boss ：载入正常经济模拟生成的第五关检查点，页面明确标记且禁止写存档。用于快速验收 Boss，不代表从首关手动通关；生产构建不包含该入口。

最新等级/仇恨验收见 `docs/reviews/2026-10-16-rank-threat.md`；v5逐排、v4连续出怪和v3战报/Boss调整记录保留在同目录，统计属于各自历史规则。当前 Boss 生命/普攻/横扫仍为 72000/55/75（全部为 P），每秒一只连续出怪，敌人数目与属性未改。12 种种子 ×3 种招募策略 × 聚灵开关的 72 条脚本路线全部进入 Boss，62 条通关；Boss 平均 54.94 秒、平均剩余生命约 50%（包含失败样本）。三条代表路线中强攻和控制通关，经济路线在 Boss 失败。这些结果不代表真实玩家通关率或流派平衡，待原作活动开放后再校准。

`scripts/campaign-simulation.ts` 共用正常经济模拟；`scripts/balance-sweep.test.ts` 输出候选对比到 `artifacts/boss-balance-comparison.json`。需要重生开发用Boss检查点时，在PowerShell运行 `$env:UPDATE_BOSS_FIXTURE='1'; npx.cmd vitest run scripts/balance-simulation.test.ts`；普通测试只检查夹具一致性。

猴、熊、6–50 关、正式美术音效、云存档和真机性能验收仍属后续范围。手机尺寸通过浏览器视口模拟检查，未替代手机实测。
