# 灵林守阵 / mingDefense

《小妖卫道》玩法研究基础上的竖屏 H5 原型。当前包含五十关内容：八种灵兽、1–6 阶、经验天赋、十位首领、远程/召唤/分裂敌人和本地检查点恢复。3格接敌规则已实现，已有控制/不聚灵和经济/聚灵的合法路线完成五十关，整体难度仍待玩家与原活动实机校准。已有来源的规则继续保留，缺失数值按用户授权设计；这不是原作数值还原完成版。

## 启动

需要 Node.js 20.19+ 或 22.12+（本机验证 Node 24.12）。

```powershell
npm.cmd install
npm.cmd run dev
```

打开 http://127.0.0.1:5173/ 。默认仅监听本机。

### 手机局域网试玩

电脑与手机连接同一Wi-Fi，电脑运行独立的局域网命令：

```powershell
npm.cmd run dev:lan
```

在手机浏览器打开终端显示的 `Network` 地址，选电脑WLAN/以太网的IPv4地址，不选WSL虚拟网卡或169.254开头的地址。原 `npm.cmd run dev` 继续仅监听本机；若5173已占用，可用 `npm.cmd run dev:lan -- --port 5174`，并打开对应端口。

手机与电脑、不同浏览器，以及不同主机名/IP/端口的存档分别保存；更换访问地址不会自动带入原进度。短屏和横屏允许上下滚动查看战场与操作区，保留棋盘清晰度；整备、战斗及弹窗适配安全区，弹窗打开时锁定背景滚动。

开发模式下，在地址后加 `?playtest=calibration40&perf=1` 可独立试玩第40关并显示性能读数，不读取或写入正式战役档。面板每秒更新，统计最近最多120帧的帧率、P95帧间隔、超过50ms的慢帧、绘制CPU耗时、敌人/攻击特效和图片池；可点击标题折叠。绘制CPU耗时仅覆盖场景更新与绘图指令生成，不含GPU呈现、React和完整模拟开销。可见页面的长卡顿计入慢帧，切出页面后重新采样；低帧率可能受窗口遮挡或浏览器节流影响，需要在前台真机上复核。

验证生产包可使用：

```powershell
npm.cmd run build
npm.cmd run preview:lan
```

手机打开终端显示的Network地址（默认4173）。生产预览保留正常游戏与本地存档，不提供开发试玩和性能入口。浏览器验收及真机待测项目见 [手机试玩验收](docs/reviews/2026-10-22-mobile-playtest.md)。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`test` 包含当前3格规则的72条固定经济策略诊断、规则及迁移测试，以及明确标记“历史1格规则”的十至四十关经济路线回归。旧路线的通关数不代表新版3格结果。`build` 包含 TypeScript 检查与生产构建。

### 50关配对平衡诊断

固定原型数值，比较原领取脚本、合法桃后移、生存天赋优先及两者组合。原脚本的强攻/控制/经济是领取优先级标签，都会尽量领取全部招募；结果不是三种纯构筑或玩家胜率。默认测试跳过大矩阵与文件输出，显式运行：

```powershell
$env:AUDIT_CAMPAIGN_BALANCE='1'
$env:AUDIT_SEED_COUNT='64'
try {
  npx.cmd vitest run tools/audit-campaign-balance.test.ts
} finally {
  Remove-Item Env:AUDIT_CAMPAIGN_BALANCE
  Remove-Item Env:AUDIT_SEED_COUNT
}
```

64种子×3领取策略×2聚灵状态×4实验，共1536条路线；前12种为历史对照，其余52种为新增验证组。`AUDIT_SEED_COUNT`支持1–128，省略时为64，设12可复跑历史试验。输出至忽略目录`artifacts/campaign-balance-audit/samples-64.json`及`summary-64.md`，保留逐关到达/胜利、同种子配对改善/退步、全灭/时限、50ms步长首次倒下者与终局阵容战报。工具不改数值或黄金检查点；结论与局限见 [平衡诊断验收](docs/reviews/2026-10-23-campaign-balance-audit.md)。

### 第8/14/20关同检查点布阵实验

从原领取脚本正常到达的开战存档独立恢复，比较原阵、同种高阶备战替换、狐覆盖调整及组合。固定规则只做合法移动/换位，不按试战结果选阵型，不改变资源、招募或数值：

```powershell
$env:AUDIT_FORMATION_REPLAY='1'
$env:FORMATION_REPLAY_SEED_COUNT='64'
try {
  npx.cmd vitest run tools/audit-formation-replay.test.ts
} finally {
  Remove-Item Env:AUDIT_FORMATION_REPLAY
  Remove-Item Env:FORMATION_REPLAY_SEED_COUNT
}
```

种子数支持1–128、默认64，设12可试跑。64种子共602个到达检查点、2408场回放；更早失败不计到达。输出`artifacts/formation-replay/samples-64.json`及`summary-64.md`，含完整开战存档/动作、胜负配对、倒下记录、输出损失、护盾和逐兽战报。原阵回放逐字段核对原路线，默认测试跳过文件输出。这是单关策略实验，验证种子沿用上一轮，不能当成50关收益或玩家胜率；狐覆盖增加并不保证胜利，尚未自动应用到玩家阵型。结论见 [同检查点布阵验收](docs/reviews/2026-10-23-formation-replay.md)。

## 启动加载与恢复

首次打开先显示「正在准备灵兽与战场」，准备完成后自动进入游戏。游戏脚本或引擎加载失败时显示恢复画面，点击「重新加载」可重新尝试；路径、查询参数及本地存档保留，战斗仍按开战检查点恢复。入口脚本本身无法执行时，HTML中的加载说明和重载链接仍可使用。恢复操作不会清档或重新开局。

Phaser已单独分包，启动入口及静态依赖约225KB；完整首次脚本仍约1.60MB，不代表总下载量或真机加载时间已降低。没有离线缓存。正常启动、三类脚本失败和恢复验证见 [启动恢复验收](docs/reviews/2026-10-22-startup-recovery.md)。

生产构建后可额外检查启动依赖，防止共享辅助代码把引擎重新带回入口：

```powershell
$env:CHECK_STARTUP_BUILD='1'
npx.cmd vitest run tools/startup-build.test.ts
Remove-Item Env:CHECK_STARTUP_BUILD
```

该工具读取既有dist，不改写构建或存档；普通测试默认跳过，需要先运行build。

## 战场图片加载

进入游戏后，棋盘会显示39张战场素材的真实处理进度（包含失败项，不是下载字节比例），首帧画面绘制后开放棋盘和「开始守阵」。未就绪期间战斗时钟冻结，恢复后不补跑等待时间。

单张图片请求8秒超时，不自动反复重试。图片失败时沿用已有几何图形、线条等简化显示，棋盘下方提示失败张数，仍能正常开战。整备时点击「重试战场图片」只重载战场画面，保留阵容、灵钱、招募和撤销；战斗时先返回布阵再重试。此入口不重试界面图标或脚本，也不提供离线缓存。实际缺图、超时、重试与窄屏检查见 [战场加载验收](docs/reviews/2026-10-22-battlefield-loading.md)。

## 战场画面中断恢复

设备释放WebGL画布时，游戏立即停止等待并显示恢复提示；当前战斗暂停，按住聚灵及未完成拖动取消。引擎恢复资源后，继续等待场景的真实首帧，随后自动关闭提示；战斗仍保持暂停，点击「继续守卫」才恢复，不补跑等待时间。当前阵容、资源和已打开面板保留。

一直无法恢复时，可选择重新加载页面。正常战斗会回到开战前布阵，本关未结算收益不保留；隔离试玩会重置临时进度。没有自动刷新、自动清档或切换渲染器。仅响应浏览器WebGL中断事件，未涵盖没有事件的所有黑屏。生命周期/时钟测试、浏览器正常流程和恢复提示布局见 [画面恢复验收](docs/reviews/2026-10-23-renderer-recovery.md)，真实设备显卡中断仍待验收。

## 天赋选择收益预览

三选一天赋卡片显示当前→选择后层数、本天赋累计加成、当前存活受益灵兽或施放者数量；专属按种类与最低阶统计，倒下者另列，备战席不计。生息额外显示此刻补足的生命总量，倒下者不会复活。保留原单层描述，点击卡片仍直接选择。

累计是该天赋本身的贡献；百分点、概率、射程与灵钱分别标明，不代表最终伤害或胜率。攻速/减速上限、残血与非首领等条件随卡片展示。预览不改变候选、随机数、时钟或存档。验证见 [天赋预览验收](docs/reviews/2026-10-23-talent-preview.md)。

## 天赋手札效果详情

点修行条的「天赋」或暂停菜单的「天赋手札」，查看已获得天赋的当前/最大层数、满层标记、累计贡献、适用范围和生效条件。破势以百分点显示，终烬明确为概率；累计仅表示本天赋贡献，不等于最终伤害。

整备区分已上阵和符合条件的备战灵兽，专属按配置最低阶统计；战斗读取本关成长与当前存活施放者，倒下者另列。长手札从顶部打开，可滚动到底部收起或用顶部按钮关闭；关闭后沿原暂停流程继续守卫。详情见 [手札验收](docs/reviews/2026-10-23-talent-journal.md)。

## 受击顺序预览

整备时展开棋盘下方的「受击顺序预览」，可切换第2/4/6列参考入口。棋盘描出当前前排的完整占格，并用「先」标记首个寻敌目标；下方按排列出名称、阶数、仇恨、占格位置和静态寻敌顺序。换位、合成、移动或撤销后自动重算，备战席与未领取招募不计入。

预览复用实际寻敌规则，固定敌人在所选入口、依次移除上一目标；实战移动、多敌人和首领技能会改变承伤，不代表阵亡顺序或伤害预测。展开时暂时隐藏范围圈，收起恢复；战斗与暂停界面隐藏。此功能仅提供当前原型规则的布阵参考，不修改数值、随机数或存档。验证见 [受击预览验收](docs/reviews/2026-10-22-targeting-preview.md)。

## 战斗伤害飘字

战斗中，敌人受到的生命伤害显示金色负数，灵兽承伤显示珊瑚色负数，护盾实际吸收显示紫色「盾 数值」。同一目标的短时伤害合并显示，1万起用万单位；最多同时保留24条，文字对象循环使用。暂停和选天赋时冻结，倍速同步；返回布阵、结算和离屏清除旧数字。系统开启减少动态效果时文字静止显示，到期消失。

数字来自相邻表现采样和实际战报，不改变伤害、仇恨或护盾计算；自然失盾、补血不会显示成承伤。密集攻击会合并、超上限会省略，生成后在同一采样前被击退的敌人可能没有飘字，因此不能代替结算战报。截图与检查见 [战斗飘字验收](docs/reviews/2026-10-22-combat-numbers.md)。

## 阵型预设

整备时点击「阵型预设」，可保存3套当前站位，查看完整占格小图和备战席。应用时只移动当前拥有的灵兽，不领取招募、不合成、不恢复资源；成功后可用「撤销」返回应用前。覆盖和删除需要在面板内确认。

当前灵兽种类、阶数、数量须与预设完全相同；招募、合成或遣散后可能需要重新保存。所有占格须已解锁且不重叠，不能部分套用。预设只保存在当前浏览器，不包含在战役备份中；开发试玩使用独立临时槽，刷新清空。读取异常时保留原数据并阻止覆盖，可重试读取。验证见 [阵型预设验收](docs/reviews/2026-10-23-formation-presets.md)。

阵容不匹配时，面板会按种类、阶数列出「按预设还缺」和「当前多出」的只数，包含备战席。高阶不折算低阶；“多出”仅相对此预设，不是遣散建议。可以保存当前站位并确认覆盖，差异不会自动补兽或部分套用。验证见 [阵容差异验收](docs/reviews/2026-10-23-formation-difference.md)。

可应用的预设会显示本次调整总数，以及场内换位、备战上阵、退回备战各几只；展开「查看逐只站位变化」，可按名称、阶数、编号核对每只灵兽的起点和终点。坐标指左上起点，多格占格见小图；预览直接取自实际应用方案。验证见 [站位预览验收](docs/reviews/2026-10-23-formation-changes.md)。

展开「对照首个受击目标」，可分别查看第2、4、6列入口在当前站位与应用预设后的首个寻敌目标，包含名称、阶数、编号、位置和仇恨。默认收起，复用实际寻敌规则；这是固定入口的静态参考，不预测伤害或阵亡顺序。验证见 [首目标对照验收](docs/reviews/2026-10-23-formation-targeting.md)。

展开「对照狐支援覆盖」，可比较当前与应用预设后的施盾可达、前排施盾可达及输出光环人数，并查看双方前排行和上阵狐数量。「查看逐兽支援变化」按实例编号列出上阵/备战、前排归属及来源狐变化，包含完整占格、狐阶数/编号/坐标；即使人数相同也能核对接收者或来源替换。仅位置变化仍见站位对照。无效预设和当前已是该站位时隐藏；只读参考，不自动选阵或预测胜负，应用和撤销沿用原操作。验证见 [狐支援对照验收](docs/reviews/2026-10-23-formation-support.md)。

展开「阵型分享码」，可生成并复制所选单套预设，带到另一浏览器或手机。粘贴后点击「校验分享码」，核对完整占格和备战席，再确认存入所选槽位；已有槽位会明确提示覆盖。取消、修改文本、切槽或收起会清除待确认预览。导入只保存站位，实际应用仍要求当前灵兽匹配、占格已解锁；不带入资源或灵兽，开发试玩导入仅临时保存。验证见 [阵型分享验收](docs/reviews/2026-10-23-formation-share.md)。

## 暂停战场详情

守卫时点击「暂停」→「战场详情」，可切换查看每只上阵灵兽的生命、当前有效护盾与剩余秒数、被敌人锁定数量，以及本关累计伤害、承伤、提供护盾、护盾吸收和产钱。默认选中被最多敌人锁定的存活者；倒下者保留记录，备战席单独标为不参战。旧战报缺失值显示「未记录」。关闭后仍保持暂停，点击「继续守卫」才恢复。

锁定包含正在接近的敌人，不预测下一击或首领横扫；承伤不含护盾吸收，提供护盾不等于有效吸收。这是只读查看，不修改阵容、数值或存档。验证见 [战场详情验收](docs/reviews/2026-10-22-battle-inspection.md)。

在所选灵兽下展开「战斗当前属性」，可查看当前战中天赋、存活狐光环后的基础命中值、射程及常态/聚灵动作间隔，并列出实际光环来源。狐显示施盾比例，桃显示固定产钱参数；倒下者明确停止行动。切换灵兽重新收起，查看技能图鉴返回保留原展开状态。直接读取本场战况，命中值未计敌方减伤等结算，不是每秒伤害；聚灵间隔是恢复后有灵气并持续按住时的参考值。验证见 [战斗当前属性验收](docs/reviews/2026-10-26-battle-stats.md)。

展开「阵线总览」可按六乘六站位直接点选灵兽，与下拉选择和下方详情同步。多格灵兽完整占位，生命细条显示当前生命比例，「锁N」表示被N只敌人锁定，「伤」表示已倒下，金框表示当前查看者。倒下者仍可查看记录，图鉴往返保留总览展开和选择。总览只显示灵兽站位，不表示敌人位置或攻击预测；手机窄屏仍可使用44px高的下拉入口。验证见 [暂停阵线总览验收](docs/reviews/2026-10-26-inspection-formation.md)。

详情默认查看「灵兽」，切到「敌人」可逐只查看场上存活实例的生命、当前锁定、冻结/霜尾缓行/易伤及剩余时间、全场迟滞天赋、衍生来源和直属存活衍生数；首领优先显示，保留阶段标记。横扫区仅列该实例已经出现的预警、目标行和剩余时间，回响另标；冻结可能推迟释放，不预测下一次技能。旧数据缺失生命上限或倍率时明确注明，不伪造。浏览器及只读对照验证见 [敌人详情验收](docs/reviews/2026-10-23-enemy-inspection.md)。

灵兽被锁定时，可展开「锁定此灵兽的敌人」查看敌人名称、独立编号与当前生命，点任一项直接进入该实例详情；敌人有存活目标时，点「查看锁定灵兽」可反向定位。快捷跳转后焦点移到对应下拉框，普通切页保留双方选择；没有有效目标时不提供跳转。列表默认收起，只反映暂停时缓存锁定，包含接近中的敌人。验证见 [双向锁定查看验收](docs/reviews/2026-10-26-inspection-links.md)。

## 后续敌袭查看

守卫中点「暂停」→「战场详情」→「后续敌袭」，查看未出场固定敌人的总数与种类，以及接下来最多8只的计划时间、剩余游戏内时间和入口列。只读本场实际出怪队列，不重新生成，也不改变出怪节奏。

暂停和选天赋时倒计时冻结，倍速影响现实等待；出场不是抵达阵线或发动攻击。召唤与分裂不计入固定队列，固定出怪结束仍需清理场上敌人。关闭详情保持暂停，点「继续守卫」才恢复。验证见 [后续敌袭验收](docs/reviews/2026-10-23-upcoming-enemies.md)。

## 灵兽换位

整备时选中已有灵兽，点击「换位」，再选另一只灵兽即可互换位置。面板显示双方换位后位置；多格按左上占格对齐，完整占格越界、未解锁或重叠时禁用并说明原因。两格备战席已满也能与上阵灵兽互换，两个备战席单位无需换位。招募需先领取。

换位保留身份和阶数，同种同阶也只交换；成功可用「撤销」恢复，结果自动保存。原有拖动和叠放合成仍按原操作。这是原型便利功能，非已考证原作规则。验证见 [换位验收](docs/reviews/2026-10-22-formation-swap.md)。

## 战报复制与导出

胜利或失败结算后，展开「保存本次战报」，可复制文本或下载Markdown，包含本场结果、收入、完整阵容站位、逐兽表现和结束时累计天赋。文本框只读，可手动全选复制；旧记录缺失字段显示「未记录」，开发隔离试玩会标明来源。

战报不能恢复进度，也不会自动保存历史；进入下关前可收藏到本地或自行下载。查看和导出不消耗资源、不重复结算，不修改现有战役存档。原导出功能及浏览器验证边界见 [战报导出验收](docs/reviews/2026-10-23-report-export.md)。

## 本地战报收藏

结算后展开「保存本次战报」，点击「收藏到本地」。整备底部、暂停菜单和结算页的「战报收藏」可重新查看当时的完整文本、复制或下载Markdown。相同文本去重，最多10份，满后提示整理，不自动删除；删除前需在面板内确认。关闭收藏保持原来的整备、结算或暂停状态。

收藏独立保存在当前浏览器地址，跨刷新和重新开局保留，不包含在战役备份中，也不能恢复进度。开发隔离试玩只临时保留本页收藏，刷新清空。读取异常保留原数据并阻止覆盖，可重试读取；重要记录请下载备份。实现和验收边界见 [战报收藏验收](docs/reviews/2026-10-23-report-collection.md)。

在收藏内展开「收藏备份 · 导出与导入」，可生成完整JSON、复制或下载，再到另一浏览器粘贴或选择JSON文件（最大1MiB）。先校验并核对新增战报全文、关卡、结果与原收藏时间，确认后合并；全文重复项跳过，不覆盖原收藏。超过10个收藏位或存储大小时整批拒绝，不会部分导入；预览后收藏发生变化须重新校验。修改输入、收起、取消或重新读取会清除预览。此备份只含收藏，不恢复战役或阵型。验证及文件选择自动验收限制见 [收藏备份验收](docs/reviews/2026-10-23-report-backup.md)。

## 整备灵兽当前属性

选中上阵、备战或未领取的灵兽招募后，属性块内可点「查看技能图鉴」，直接打开该种灵兽的实际阶数；图鉴内仍可切换八灵和六阶，关闭后保留整备选择。暂停「战场详情」也提供所选灵兽的入口，关闭图鉴会回到同一实例，守卫保持暂停。图鉴显示基础值，不计本轮天赋和站位加成；扩地令无此入口。验证见 [技能快捷查看验收](docs/reviews/2026-10-26-context-handbook.md)。

选中已上阵灵兽后，展开「当前站位属性」，可比较基础与当前天赋、站位光环后的最大生命、基础命中值、动作间隔与射程，并查看聚灵时动作间隔和覆盖自己的狐光环来源。狐改列单次施盾比例，桃改列固定产钱间隔；备战和未领取招募不计算站位属性。更换选中对象时重新收起，移动、合成或撤销后重新选择即可查看更新。

基础命中值未计敌方减伤、易伤、条件增伤及技能追加，不是DPS；动作间隔按游戏步长取整，聚灵需灵气，不预测首次命中。查看不修改阵容、数值或存档。真实战斗对照与390/320宽浏览器验收见 [整备属性验收](docs/reviews/2026-10-23-preparation-stats.md)。

## 战前检查

整备操作内的「战前检查」默认收起，展开可查看上阵/输出数量、参战生命上限和已解锁空格，并按备战席、未领取招募列出当前完整落点与可合成目标数；扩地令单列可扩地位置。碎片空格不算多格灵兽的完整落点，备战和招募不计入参战生命。空阵容或只有产钱/护盾时会提醒。

点击条目只选中对象，仍需自己部署、扩地或进入合成预览；查看不消耗资源，布阵及撤销后即时更新。面板不预测胜负，也不增加开战弹窗或条件，战斗中隐藏。验证见 [战前检查验收](docs/reviews/2026-10-23-preparation-check.md)。

备战席有同种更高阶灵兽且能合法换位时，摘要会显示「同种高阶N只」（按备战来源计数）。展开可查看高阶备战及同种低阶上阵目标的阶数、编号和完整占格；目标列表默认收起。点「选中备战」或「查看上阵」仅选择对象，再用原「换位」操作手动交换，支持撤销。一次只换一对，满备战席也可换位，换位或合成后提示即时更新。验证见 [同种高阶备战提示验收](docs/reviews/2026-10-23-reserve-upgrade-hint.md)。

「狐支援覆盖」显示全队施盾可达、当前前排施盾可达及输出光环人数。展开「查看逐兽覆盖」，可核对每只上阵灵兽的完整占格和狐来源（阶数、编号、坐标），点「查看灵兽」仅选中，移动或撤销后即时更新。按中心距离判断，施盾含狐自身和桃；攻击光环只统计输出灵兽，多狐不叠加，射程天赋不扩大光环。施盾可达不保证下一次获盾，覆盖不预测存活或胜负。备战和未领取招募不提供支援。验证见 [狐支援覆盖验收](docs/reviews/2026-10-23-fox-support.md)。

## 合成预览

整备时选中灵兽或未领取的灵兽招募，点击「合成预览」，可比较升阶前后的单只基础属性、查看新增阶数技能，以及两只合计生命变为一只后的变化。选择已领取的同种同阶目标后，面板显示合成保留的位置与完整占格，再确认合成；备战席目标合成后仍不参战。无候选或已达本模式最高阶时无法确认。

查看与取消不消耗资源，确认沿用既有合成与自动保存，成功后可撤销。原点击/拖动叠放操作继续可用；这是原型便利功能，非已考证原作规则。验证见 [合成预览验收](docs/reviews/2026-10-23-merge-preview.md)。

## 布阵范围预览

整备时点选已上阵灵兽，可查看以整体中心计算的寻敌射程；选中招募或备战席灵兽后，将指针移到棋盘、拖动或用Tab聚焦格子，可预览落点。金圈为攻击型灵兽的寻敌范围，紫圈为狐的施盾范围，三阶起金色虚线为光环，并标记可覆盖的上阵伙伴。攻击/施盾带入本轮射程天赋，光环半径固定；桃不显示攻击圈。

范围只作预览，不改变布阵或存档；同阶合成按升阶后预览，非法落点不画圈，开战后自动隐藏。寻敌圈不是群攻、贯穿或散射的最终命中区域。验证见 [布阵范围验收](docs/reviews/2026-10-22-preparation-range.md)。

## 第一局与五十关流程

第1关整备时显示可收起的「首战指引」，按当前阵容提示招募、部署、同种同阶合成和开战。提示按钮只选中灵兽，仍需自己点击棋盘或拖动；备战席、撤销和刷新后会重新判断。进入战斗及第2关后隐藏。可用 [独立首战试玩](http://127.0.0.1:5173/?playtest=onboarding) 体验，该开发入口不读取或写入正式存档，刷新重开，不进入生产包。详见 [首战指引验收](docs/reviews/2026-10-21-first-battle-guide.md)。

整备界面提供完整格子、占位、招募与备战席；开始守阵后切换为紧凑战斗界面，收起布阵底格，顶部显示阵容生命、剩余时间、波次与出怪进度，底部为聚灵与倍速。点击右上角暂停，可查看敌情、天赋、玩法说明或确认返回布阵。返回调整或进入下一关时恢复整备布局。界面验收见 [整备与守卫界面](docs/reviews/2026-10-21-preparation-combat-ui.md)。

整备页右上角「图鉴」和战斗暂停菜单「灵兽图鉴」可查看八灵的1–6阶基础属性、实心占格示意及技能解锁。桃显示产钱间隔，狐显示护盾量；属性不含本轮天赋等加成，数值仍为待实机校准的当前原型配置。关闭图鉴保留整备选择；战斗中关闭后仍暂停，点击「继续守卫」才恢复。详见 [灵兽图鉴验收](docs/reviews/2026-10-22-spirit-handbook.md)。

1. 领取一只烬灵鼠，部署在第 2 列第 4 行；另一只鼠叠放上去合成 2 阶。
2. 岩甲豚放第 3 列第 4 行，横占两格；青锋隼放第 4 列第 5 行，占 2×2 格。
3. 开始守阵。灵兽自动攻击，击杀积累经验；升级会暂停并提供最多三项天赋，选择后继续。
   开场后每秒一只连续出怪，波次之间不留空档，也不等待上一波清完；本关配置出完后停止生成。
4. 按住聚灵石消耗灵气提升攻速。暂停、切出页面、失焦和升级选择都会清除按住状态；继续时重新按住。支持 1×/2× 速度。
5. 胜利后结算通关、产钱及天赋收入，进入下一关整备时免费刷新三张招募，覆盖上一关未领取的招募。阵容、格子及修行保留，下次开战全员满血。失败重试或返回布阵不会刷新招募。
6. 第 5 关首领会横扫预警，低血进入二阶段并召唤小怪；所有波次、首领、已生成小怪及已释放伤害事件结束后才胜利。
7. 第6关起英雄招募有15%概率为二阶；狼每存活10秒增加5%攻击，最多六层。新增翎羽客远程攻击、鸣咒犬周期召唤、裂岩犀死亡分裂。鸣咒犬出生10秒后首次召2只咒影，之后每20秒召2只，每只鸣咒犬最多保有6只；冻结推迟时钟，父怪死亡停止未来召唤。远程也先清前排；召唤物无经验/灵气，碎片各2经验/灵气、不再分裂。

## 存档与重试

本地自动保存整备、关后待选天赋和完成状态。战斗中刷新、失败重试或中止会回到完整的开战检查点，本关产钱、经验和天赋全部回滚。通关奖励每关只结算一次。“重新开始”清空本轮进度。

整备页底部「存档」、战斗暂停菜单及胜负结算中的「存档备份与恢复」支持手动迁移进度：

1. 点击「下载备份文件」，或生成完整备份文本后复制保存。自动复制受浏览器权限和安全上下文限制，不可用时可在文本框中手动全选复制。
2. 在另一浏览器或手机打开正常游戏地址，进入存档弹窗，选择JSON文件或粘贴完整文本，校验后查看关卡、修行、灵钱、灵兽数量及状态。
3. 确认替换后才写入并恢复。可取消或继续编辑，当前进度不会提前改变；已知旧版按现有规则迁移，不重复发奖。
4. 替换前保留一份本地备份，可用「读取替换前备份」预览后确认恢复；仅保留最近一次，不是多存档槽。读取或写入失败时不替换当前进度。

支持最大1MiB的备份JSON及既有原始存档。战斗中备份只保留开战检查点，关闭弹窗后仍暂停，需主动继续守卫。备份不含音乐/音效偏好，不提供账号或云同步；开发试玩不能导出或导入正式进度。文件下载和选择的系统界面因浏览器而异，详情及验收边界见 [存档备份验收](docs/reviews/2026-10-22-save-transfer.md)。

存档键为 `ming-defense:campaign`，按 `schemaVersion` 和 `contentVersion` 验证。旧版本或损坏数据先备份再开始新局；备份失败保留原档并停止覆盖。存储不可用时仍可玩，但刷新可能丢失新进度。数据仅在当前浏览器本地保存，未实现账号和云同步。

当前内容版本为 `prototype-2026-10-22-v24`。已知 v2/v3/v4/v5/v6/v7/v8/v9/v10/v11/v12/v13/v14/v15/v16/v17/v18/v19/v20/v21/v22/v23 可在备份后自动迁移，保留阵容、灵钱、成长和关卡，后续新战采用当前战斗规则；旧胜利战报保留原结果，缺少逐兽数据时提供说明。旧第五/十/十五/二十/二十五/三十/三十五/四十/四十五关完成档可继续第六/十一/十六/二十一/二十六/三十一/三十六/四十一/四十六关，既有奖励不重复，进入下一关时仅免费刷新一次招募。迁移备份/写入失败时原主档保留，本轮停止自动覆盖。其他未知版本仍按上述不兼容流程处理。

## 结构与校准

- `src/game/content.ts` 直接读取 `docs/superpowers/specs/2026-10-14-prototype-balance.json`，数值以该 JSON 为准，v1 快照单独保留。改数值时同步更新内容版本及对应规则说明。
- `session.ts` 管理招募、布局、合成、阶段和收益事务；商店、天赋、战斗使用独立可序列化随机状态。
- `combat.ts` / `combat-skills.ts` / `combat-projectiles.ts` / `enemy-abilities.ts` / `combat-model.ts` 是独立 50ms 模拟器，不依赖 React/Phaser；批量伤害支持同帧互杀先判负，死亡取消未释放攻击，已释放剑阵与鹰/猴双段继续生效。新易伤在本步伤害结束后施加，已有易伤乘算普通伤害；不叠加，多猴取较高值并刷新持续时间。斩杀直接移除剩余生命，不受减伤/易伤影响，只统计实际生命损失。
- `combat-diagnostics.ts` 提供可选生命周期观测，记录出生/死亡边界，包含同一步被消灭的召唤物；不进入存档，不参与随机数和战斗决策。
- `progression.ts` 处理经验、天赋条件、品质权重和上限；`persistence.ts` 验证存档并处理恢复。
- `clock.ts` 处理速度与暂停，不追补离屏时间；`ui/game-loop.ts` 用独立25ms计时器推进50ms固定模拟步长，HUD最多10次/秒，模拟不依赖视觉帧回调。`render/Battlefield.tsx` 用 Phaser 绘制现有美术与缺图占位，`ui` 提供 DOM 操作及 HUD。
