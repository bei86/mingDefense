# 第8、14、20关同检查点布阵实验

日期2026-10-23；配置`prototype-2026-10-22-v24`，三格接敌。

## 结论

完成602个合法开战检查点、四种方案共2408场回放。狐的静态覆盖数增加并不稳定改善战果：第8关净少1胜、第14关净多4胜、第20关净少6胜。不能把覆盖最大化脚本包装成自动布阵或最优策略。

同种高阶备战替换仅25个检查点有操作，2场败转胜、0场胜转败；这2场是同一种子/同一领取策略的聚灵开关对照，不是两个独立种子。适合下一步做可核对的备战提示，不支持“换高阶必胜”的结论。保留现有数值和玩家自主布阵。

本轮交付共用单关执行器、固定布阵规则、独立恢复回放、配对汇总与复跑工具。无游戏运行时/UI/存档格式/依赖/数值/黄金fixtures变更；未提交或推送，保留此前阵型分享和平衡诊断的工作区改动。

## 实验设计与限制

- 种子20261014–20261077，3种原领取标签×聚灵开关。原路线只跑到第20关，提取真实到达的第8/14/20关开战存档；分别326/207/69份，共602份。更早失败不计后关到达。
- 原阵、同种高阶替换、狐覆盖、先替换再调狐四实验，每份独立恢复；所有动作走Session.transfer/swap，无注入、领取、合成、遣散、扩地或重掷。无操作也完整计入配对。
- 高阶替换：初始备战按阶数降序、ID升序，选同种严格低阶的上阵目标，目标按阶数、ID升序；每只初始备战最多一次，备战满可直接交换，多格完整合法。不把不同种类的阶数直接比较。
- 狐调整：上阵狐按ID各最多一次合法移动或与非狐上阵单位换位；候选按行列顺序。优先提高“至少有一只达阶数门槛狐覆盖的输出灵兽数”，同分再提高“前排至少有一只狐能施盾的灵兽数”。只接受严格提升，不反复试战或选择终局最好的阵型。
- 攻击光环按配置门槛/半径及实际多格中心；多狐覆盖只计一次。施盾范围用heroRange含射程天赋，和攻击光环分开。静态计数没有包含完整承伤顺序、技能释放、输出价值权重或后续走位，不代表护盾吞吐/DPS/存活预测。
- 每场沿原领取标签的天赋选择优先级与聚灵规则。初始资源、成长、招募和各RNG完全相同；开战后击杀顺序与上阵灵兽会改变经验、候选和随机流，所以不是强制同一天赋选择序列的实验。
- 前12种历史组；其余52种是上一轮已经使用的验证组，不能称本轮全新留出组。本轮没有根据结果修改规则再重测，未做统计显著性推断，路线相关性也不是独立玩家样本。
- 比较对象是单关胜负，不继续用变体结算推进后关，不据此计算变体50关通关率。首次倒下及全部倒下按50ms步长、同步按ID观察；没有敌方类型的伤害归因。

## 可核查例子

### 高阶换入有效的局部案例

`20261055 / assault / 聚灵关 / 第8关`：备战编号140的2阶岩甲豚与上阵编号133的1阶岩甲豚交换，完整横2格落在(1,0)。原阵78950ms全灭、输出倒下9只，首次输出倒下10300ms，终局剩11只翎羽客；换入后47000ms获胜、剩生命4592、输出倒下4只，首次输出倒下13300ms。

攻击光环覆盖均为5只，前排施盾覆盖均为0。有效护盾吸收从966变为102；更短战斗和不同承伤会改变吸收总量，不能把吸收较少本身判成更差。该种子的聚灵开版本也败转胜，是本轮全部2场替换救回样本。

### 狐覆盖改善战果的案例

`20261014 / assault / 聚灵开 / 第14关`：5阶狐从(1,5)移到(2,4)；4阶狐从(0,4)与(2,2)的3阶岩甲豚交换。输出光环覆盖3→10，前排施盾覆盖0→3。原阵69650ms全灭，调整后62350ms胜利、剩生命3237；输出倒下12→8。首次输出倒下均12250ms，有效护盾吸收1130→914。

这同时改变狐与被交换豚的位置、输出覆盖和后续战斗过程，不能将收益单独归因于光环或施盾。

### 覆盖更多仍失败的反例

`20261014 / control / 聚灵关 / 第20关`：6阶狐从(2,5)与(5,3)的5阶桃交换，输出光环覆盖10→13，前排施盾覆盖保持3。原阵72700ms获胜、剩生命3427；调整后80400ms全灭，终局剩首领、6只翎羽客、4只咒影。输出倒下11→13，首次输出倒下均7750ms，有效护盾吸收1868→1693。

覆盖评分确实提高，但未保护原胜局。上例只证实这个评分不能保证更好战果，不能据终局敌人数或吸收差直接断定具体敌方伤害来源。

所有坐标为0起点左上坐标。完整开战阵容、实际动作及逐兽数据见JSON。

## 后续开发建议

下一项优先做玩家可核对的战前提示：已有同种更高阶备战、当前低阶上阵目标及完整占位，点击只选中灵兽，沿用现有手动换位和撤销。不要自动移动，不许用“必胜/最佳”措辞。

狐布局仍需要将前排存活、关键输出与实际射程纳入事先固定的新策略，另用未参与选择的新种子验证，或先由玩家在活动实机体验后校准。当前不把本轮试验脚本接成自动布阵，也不依据单关对照全局降难。
