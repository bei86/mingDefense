# 战斗独立调度验收

日期：2026-10-21，内容版本仍为prototype-2026-10-21-v17。本轮接在三格接敌与清晰度修正之后，先处理前序多次验收记录中的战斗推进缓慢。

## 改动与原因

此前App通过requestAnimationFrame调用GameClock，Phaser另有视觉循环；模拟依赖视觉回调。临时探针在验收环境中没有获得连续的RAF记录，无法把问题认定为CPU瓶颈或关卡数值错误。本轮将模拟调度独立出来，修正这项依赖，未放宽卡顿保护。

src/ui/game-loop.ts以25ms计时器调用GameClock.advance(performance.now())，继续按50ms固定步长运行，HUD最多10次/秒。App挂载启用，卸载/热更新清理计时器并重置时钟，避免补算卸载间隔。Phaser保持原视觉循环与画布分辨率。

超过250ms的单次长停顿仍被丢弃，暂停、后台、失焦和天赋选择仍停止模拟并清除按住聚灵状态。没有改变3格距离、技能、攻击、生命、连续出怪、速度倍率、经济或存档内容版本。临时探针全部移除。

- 新增7项调度测试：1×/2×在没有RAF时准确推进且HUD为10Hz；完整战斗逐步与直接50ms仿真一致；暂停与天赋停表；长卡顿丢弃后恢复；卸载清理及重新挂载只有一个计时器。
- 定向92项通过，完整回归271项通过、15项环境变量门控工具跳过。命令：npm test -- --maxWorkers=2 --reporter=dot。
- npm run build通过，Phaser已有主包大于500kB提示保留。生产包检查临时探针、开发场景与测试辅助器不进入产物。
- simplify自审：独立调度器仅一个计时器，无额外React状态、循环抽象或新依赖；GameClock与Session规则层未改动。保留所有前序未提交的UI/接敌改动，不自动Git提交或推送。
