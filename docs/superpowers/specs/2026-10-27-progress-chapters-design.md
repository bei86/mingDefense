# 战役进度分段浏览设计

当前“提交并下一步”沿用持续授权：提交上一轮后，当前会话顺序设计、实施和验收，不派代理、不重复审批。本轮新开发留工作区。上一轮提交为 `13acb71`。

## 问题与选择

进度窗口每次从第1关开始，后期玩家要翻过多组关卡才能看到当前关；从敌情返回也回到列表顶部。保留全量长列表加滚动定位需要额外协调焦点与滚动，逐关翻页又增加操作。选择原生下拉分段：默认当前所在10关，可选择五个分段或全部50关，另有“当前分段”按钮快速返回。沿用既有主题，不增加常驻战斗界面。

## 行为

整备、暂停、结算每次打开进度都显示实际当前关所在分段：第10关仍为1—10，第11关为11—20，第40关为31—40，第50关为41—50。下拉选项标明哪个分段包含当前关，全部关卡选项显示50关。切换只影响列表，顶部通关/首领总数、当前关名与状态不变；未显示当前关的分段不制造当前标记。

“当前分段”将筛选改回当前分段，在当前分段时禁用。查看任何关卡敌情后，返回保留所选分段，包括全部模式；维持原焦点规则，返回先聚焦顶部关闭，列表回所选分段顶部，不承诺恢复逐像素滚动。完全关闭再打开重新选当前分段。隔离来源和单关限制提示保持。

## 实现与边界

App将进度可见布尔改为可空的浏览状态 `{ chapter: number } | null`：null关闭，0全部，1—5对应分段。三个入口用当前stageId初始化，筛选由App持有，因此敌情暂时卸载进度也不丢失。模态焦点context只依赖进度是否打开，切换筛选不重置焦点。组件从既有只读模型筛选分组，不调用Session动作，不写本地存储。

复用单一分段计算函数，覆盖10/11、40/41边界。原生select与按钮至少44px高，280宽允许控件换行；保留5列及极窄4列关卡按钮和内部滚动。

不改规则、随机、三格距离、contentv24/schema2、存档格式、fixture、素材、依赖或npm命令。生产与DEV都提供分段，DEV入口仍从生产排除。

## 验收

模型边界与SSR核对后期当前分段、其他分段、全部模式、总统计不变、来源提示及无渲染动作。浏览器经正常UI验证正式结算默认分段、切换/敌情往返/完全重开、隔离第50关默认41—50及暂停不继续、390/320/280宽、键盘焦点与生产入口；保存截图。全量测试、构建、显式启动检查、Prettier及diff检查；桌面尺寸模拟不当作手机实测。
