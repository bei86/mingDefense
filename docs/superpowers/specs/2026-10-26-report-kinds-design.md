# 结算同种灵兽贡献汇总设计

用户持续授权“提交并下一步”，本轮先提交多维排序，再完成同种汇总。

## 目标与取舍

逐兽排序能定位单只贡献，但多只同种灵兽的总贡献需要自行相加。在同一战报内增加「逐只查看 / 同种汇总」原生选择，沿用五种排序指标。默认逐只，切换保留排序，比另建排行榜或扩展持久战报格式更便于复盘，也保留窄屏四列表。

## 行为

- 同种汇总按战斗上阵实例归组，包括重伤者，排除备战与未参战者。不同阶的同种灵兽相加，列出各阶只数、总只数、重伤只数；不把合计解释为单只强度。
- 伤害、承伤、施盾、吸收、产钱分别求和，口径沿用战报，不新增结算。表格保留伤害/承伤/产钱三数值列，护盾在名称下展示。
- 同种指标只有在每个成员都有有限数值记录时才显示合计；部分成员缺失显示「未完整记录」，全部缺失显示「未记录」。任意缺失都排在完整值（包括0）之后。同值按既有八灵顺序。
- 排序和显示模式仅局部state，收起重开保留，两种查看共享一个指标。切回逐只仍保留原编号、站位、重伤和排序。
- 没有旧战报时保留原提示，不提供伪造合计。表格caption标明「同种合计」与排序，补充不同阶相加、数量差异及缺失口径。
- 不修改模拟规则/数值、RNG、schema2/contentv24、3格接敌、存档、导出、收藏、依赖、素材或原npm命令。

## 结构与验证

`report-kinds.ts`只读投影，按battle.allies关联report.units，五指标聚合，复用reportValue与reportMetrics。`ReportUnits.tsx`增加模式选择和同种表；共享排序选择与表头，保持局部状态，不新增effect或缓存。

测试覆盖不同阶/同名/重伤/备战、五指标守恒、部分及全部缺失、0、稳定排序、空战报、只读与真实完整战斗的存档/导出不变；SSR核对合计口径。浏览器独立试玩正常布置两只同种灵兽并完成一关，对照逐只与同种表，切换指标、收起和下一关操作，检查390/320宽、截图与控制台。

自审：不做跨种类强度排名或胜率推荐；缺失不能累加为0，备战不能增加只数；施盾和吸收独立，失败产钱不等于实际入账。范围限于当前结算呈现。
