# 存档备份与恢复设计

本轮承接用户“提交并开发下一步”：五十关已以db95368中文提交。现在完整长局已有跨浏览器、手机局域网试玩需求，先补本地手动备份恢复，再考虑在线存档或新的玩法模式。相比直接接云服务，该方案沿现有本地检查点实现、无需账号和服务器；相比继续加关，更先解决已有50关进度的保留。用户已授权本轮开发，原生执行，新开发保留工作区不自动提交或推送。

在整备页增加「存档」工具，暂停菜单和结果弹窗提供同一入口。沿用森林绿、浅金边框与DOM弹窗，关闭恢复原界面；战斗打开后保持暂停，关闭不自动继续。文字和按钮只在弹窗中出现，不挤占战场。320和390宽允许弹窗内部滚动。

支持生成当前备份、复制文本、下载JSON、选择JSON文件或粘贴文本校验。复制不可用时仍可手动全选文本。备份封装format=ming-defense-backup、backupVersion=1、exportedAt和save，接受相同封装及既有原始SessionSave。最大1MiB，文件先检查size再读取。导出战斗/失败状态沿Session.exportSave回到开战检查点，明确本关临时收益不保留；关后待选和完成态原样保留，不重结算。

导入先做纯解析、已有结构校验和已知v2–v23版本迁移，只预览关卡、模式、状态、修行、灵钱、阵容数和是否升级，绝不在预览时触碰正式存储。用户点击「确认替换当前进度」才保存。确认区展示当前和待导入关卡，说明当前进度会替换。取消、编辑文本或重新选文件使旧预览失效。

替换时先读取现有主档，将当前会话检查点和原主档原文一起保留在固定的before-import备份槽，再写新主档；任何读取或写入失败不切换会话，原主档保持。槽仅保存最近一次替换前进度，弹窗可读取该槽、预览并确认恢复；恢复本身也采用同一替换事务。成功后由App外层替换Session并重挂载游戏界面，清除旧选择、计时器、音频、复盘与保存监听，避免reload/pagehide把旧会话重新写回。

开发试玩设置显式isolated标记，备份恢复入口保留说明但禁用读写与导出，避免将测试检查点导入正式战役。正式存储失败的会话仍允许导出自救，不能把blocked误作开发试玩。音效偏好不随战役导入，玩法数值、schemaVersion和contentVersion均不变，不新增依赖。

验收覆盖整备/战斗/失败/关后天赋/50完成态往返、已知旧45续关不重奖、损坏/不兼容/超限/非法占位、预览零写入、备份和主写失败原档保留、最近备份恢复与Session替换监听清理。浏览器在独立端口正式新档进行导出/损坏输入/有效预览/取消/确认/重载与恢复，以及DEV隔离、暂停保持和320/390布局。真实手机文件分享与系统下载UI不作为浏览器模拟已验证事实。
