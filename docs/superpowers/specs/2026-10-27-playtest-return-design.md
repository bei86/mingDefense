# 试玩往返与结算切换设计

用户“提交并下一步”持续授权当前会话顺序设计、实施和自审，不派代理、不重复审批。上一轮已提交 `f4c8011`；本轮新开发留工作区，不提交不推送。

## 目标与方案

集中试玩入口目前能进入场景，但无法从菜单返回正式战役，结算后也无法打开统一菜单。采用扩展现有菜单及结算动作的方案：复用整备/暂停入口，新增DEV结算入口，在隔离试玩的弹窗中提供“返回正式战役”。相比常驻悬浮工具条，这不增加战斗遮挡；相比把正式战役列入场景下拉，明确区分临时场景与原有检查点。

PlaytestLauncher接收phase和isolated，分别显示“返回布阵”“返回暂停菜单”“返回结算”。隔离时才提供“返回正式战役”，文字说明离开会丢弃未保存操作、临时试玩进度，需先导出；正式战役按正常检查点加载，无正式档则正常新局，不把试玩阵容带入。

点击返回仅location.assign当前pathname，不带playtest/perf/case/variant/hash；选择或关闭不导航。菜单渲染不预读正式存储，不调用Session重置、导出、保存或恢复。实际返回后复用正常loader的检查点/损坏档/不可用存储处理。

DEV的ResultModal增加可选onPlaytests入口，胜利/失败（含第8关专用结果）均可打开；关闭不改变结果、天赋和奖励。上层top-modal及useModalFocus维持焦点循环，返回结算后按既有弹窗规则聚焦结算内首个控件。待选天赋期间沿用原流程，不额外插入入口。
