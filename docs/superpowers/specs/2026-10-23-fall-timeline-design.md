# 战报重伤时间线设计

日期：2026-10-23

## 目的与方案

战后仅有累计承伤，无法判断哪个位置先失守。本轮在现有逐兽战报中增加轻量重伤时间线，同时进入Markdown、收藏及收藏备份。选择记录重伤批次而非只记首个重伤者，便于观察阵线持续崩溃；不做逐帧回放，避免存储与操作复杂度。

## 记录语义

- `BattleReport.falls?: { at: number; unitIds: number[] }[]`；新战斗初始化空数组，旧战报缺字段表示未记录。
- 每个实际50ms模拟步完成伤害和敌方死亡处理、推进时间后，追加此前未记录的重伤参战灵兽；同一步为一批，以ID稳定排列，不推断批内先后。
- 时间为该步结束时的游戏内模拟时间，精度0.05秒。暂停、天赋等待、结算后的tick不追加；聚灵与倍速沿用原有模拟。
- 每只参战灵兽最多一次，备战席不加入。重试或下一关创建新报告。
- 记录只观察生命，不改变攻击、仇恨、伤害、奖励、RNG或任何数值。

## 展示与兼容

- 在默认收起的逐兽战报内显示重伤时间线，以时间、名称、阶数、锚点列行识别实例。同帧并列显示，并注明50ms观测精度。
- 空数组显示“本关无灵兽重伤”；旧报告或旧逐兽记录缺此字段显示“这份旧战报未记录重伤时间”。不从累计承伤猜测顺序。
- 导出使用相同文本语义，收藏保存导出全文，因此无需修改收藏格式和备份版本。
- 胜利检查点保留新字段，存档schemaVersion和contentVersion不变；缺字段仍兼容。存在字段时严格验证时间递增/范围/整数、非空批次、ID唯一且属于重伤参战者、覆盖全部重伤者，拒绝无效新数据。

## 验收

真实普攻、首领横扫、同帧互杀和多步重伤；同帧批次、只记一次、护盾吸收不误判；旧报告、无重伤和重试清空；含/不含观测的完整模拟状态与RNG一致。胜利存档往返、非法字段拒绝；导出及收藏全文保留。浏览器完成真实战斗，验证时间线、导出与窄屏，保存截图。仅观察，不修改正式浏览器存档。
