# 狐支援覆盖检查

用户继续授权「提交并下一步」。上一轮已提交`5d0cb74 新增同种高阶备战灵兽换位提示`。本轮顺序实现，完成后留工作区，不推送。

## 方案与范围

已有选中狐的棋盘范围圈，但缺少整队逐兽核对。采用战前检查内的覆盖摘要与默认折叠逐兽列表；自动调位会改变玩家阵型，单纯扩大画面标记会增加棋盘遮挡，因此本轮用可展开的只读列表。静态覆盖不是护盾实际分配、存活或胜率预测。

- 独立纯模型`foxSupport(preparation)`只读已上阵单位，排除备战与所有招募。每只单位按种类中心计算，与实战`shieldTarget`同样使用`heroRange`及距离；射程天赋只扩大施盾半径。狐自身可成为施盾目标，桃可施盾。
- 攻击光环来源必须达到配置阶数门槛，使用固定光环半径，不随射程天赋扩大。只把有输出的六种灵兽计为攻击受益者，桃和狐明确不计输出；多狐只按被覆盖的灵兽去重计数，不叠加攻击百分比。
- 前排按上阵单位最上占格所在行，与实际寻敌一致；多格单位计一只，使用中心距离而非最近占格。结果包含来源的编号、阶数和坐标，以及每只上阵单位的完整占格副本，不泄漏原位置引用。列表按行/列/编号排序。
- 在展开的战前检查显示「狐支援覆盖」，摘要三项：施盾可达N/上阵数、前排施盾可达N/前排数、输出光环N/输出数。空阵容显示先部署；无上阵狐说明备战/待领不提供支援。前排行号从1显示。
- 「查看逐兽覆盖」默认收起；每只列名称、阶数、编号、完整占格、当前前排标记、施盾/攻击光环来源（含阶数编号坐标），没有覆盖明确显示。可点击查看灵兽，仅沿用choose选择，重复点击保持选中，fieldReady为假时禁用。不加入自动换位或布阵建议。
- 文案解释中心距离、狐可为自己施盾、一次一目标、按护盾比例选择和多狐光环不叠加。每次布阵/合成/换位/撤销即时重算，战斗随整备隐藏；长列表沿页面滚动，按钮至少44px，320/390宽可读。
- 不改数值、规则、3格接敌、RNG、存档格式、启动命令、依赖或既有范围圈。新模型仅在战前检查展开时计算；React不保存重复派生状态，不引入effect或不必要memo。
