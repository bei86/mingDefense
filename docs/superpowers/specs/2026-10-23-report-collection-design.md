# 本地战报收藏

## 目的与方案

当前结算战报进入下一关后无法从游戏中重新查看。增加手动收藏：结算页展开原「保存本次战报」，点击「收藏到本地」保存当时的完整文本；整备底部、暂停菜单和结算页提供「战报收藏」。用户持续授权自主“提交并下一步”，本轮顺序执行，不再设置方案确认，不派代理；新功能待下一次用户要求再提交。

在自动记录每场、手动收藏与仅文件下载三种方案中选择手动收藏。自动记录需要可靠的场次标识及更复杂的去重生命周期；手动收藏复用现有结算文本、明确保存意图，也保留文件下载。先提供10个收藏位；满时拒绝新增并提示删除，不自动淘汰。完全相同文本去重，不消耗槽位。

## 交互与数据

默认不自动记录。收藏列表按保存顺序倒序，显示关卡、结果、收藏时间；原生下拉选择后显示当时文本，可复制/下载。文本以textarea只读呈现，不渲染外来HTML。删除当前收藏先在面板内确认，取消不写；空列表提示去结算页收藏。关闭保持原界面与暂停状态，不恢复战斗、不改阵容。

保存文档快照，不存Session或战役恢复数据。独立localStorage键ming-defense:report-collection，schemaVersion1，最多10条，单文档文本不超过64KiB，总记录不超过768KiB。每条含id、createdAt、stageId、result和document(fileName/text)。文件名只接受现有导出的固定安全格式。字段、版本、大小、重复ID/文本校验失败保留原始值并禁止写入/删除，可重试读取；配额异常不声称成功。每次修改先重读，避免覆盖其他页面已保存条目，但不承诺同时写入的原子合并。

开发隔离试玩使用当前GameApp生命周期内的内存StoragePort，不触碰正式收藏，刷新清空；面板和保存成功提示明确临时性。正常收藏跨刷新、新局保留，换浏览器/地址独立，不包含在战役备份内。复制与下载复用同一组件，保留手动全选退路。读取仅在打开收藏或手动保存时发生，不增加游戏循环存储访问。

## 实现与验证

新增report-collection.ts负责快照、校验、独立读写和临时StoragePort；ReportText.tsx复用复制下载与只读文本；ReportCollection.tsx负责列表、刷新、确认删除；App只接入存储对象与开关，沿用useModalFocus。现有ReportExport只加收藏入口，ResultModal与PauseMenu传递打开事件。

不改核心数值、战斗、v24/schema2、RNG、依赖、美术及默认命令。测试覆盖真实胜败结算、未结算拒绝、快照独立、重复/容量/删除、异常格式与配额保留、内存隔离和真实Session无副作用。浏览器正常首战收藏→下一关查看→刷新恢复，并检查隔离、删除取消确认、暂停关闭、390/320布局和最终生产包；不以模拟视口代替真机。
