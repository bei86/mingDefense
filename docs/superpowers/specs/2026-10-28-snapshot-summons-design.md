# 快照召唤状态设计

用户持续授权“提交并下一步”。上一轮已提交f497dbb；本轮原生顺序实施、自审和验收，不派代理、不额外审批，新开发留工作区。

## 范围与方案

暂停快照已有双方普攻准备，但召唤状态只在敌人详情可见。推荐在原快照增加独立“敌人当前召唤”章节，复用enemyInspection已经读取的summon。另一方案将召唤混入普攻章节会混淆两个周期；增加新的常驻战斗面板会占用战场，也无法随快照分享。本轮采用独立章节，不增加常驻控件。

按原存活敌人顺序，只列summon非空的首领与鸣咒犬，逐实例保留名称和编号。章位置在横扫说明之后、未出场固定队列之前，强调召唤与固定队列不同。没有来源时明确“当前无存活召唤来源”。倒下来源不导出旧计时。

## 数据与语义

- 已启用来源记录当前计时。0为待判定，正数沿enemySeconds向上保留一位小数，null为召唤计时未记录，不能补成0。
- 冻结来源分列冻结剩余与解冻后召唤计时；解冻后计时0为待解冻，不能声称将立即生成。
- 未启用首领仅沿phaseRecorded说明阶段与启用阈值，低生命不能提前视为第二阶段。旧字段缺阶段则注明无法确认，不按生命推测。开场启用但阶段未记录时仍显示真实计时，单次数量注明按未强化参数显示。
- 各来源记录直属存活咒影/上限、当前单次召唤参数和后续间隔。复用summon.living，不计其他来源、孙代、倒下者和分裂碎片，不自行推断未来实际数量。
- 到点仍按空位结算，满额时本次可能不生成并按周期再判定；未生成召唤物不计入尚未出场的固定队列。快照只供观察，不能预测生成结果或恢复战斗。
