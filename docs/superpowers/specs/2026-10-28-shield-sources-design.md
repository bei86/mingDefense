# 战斗施盾可达来源

## 目标与方案

选中任意上阵灵兽、展开「战斗当前属性」后，查看当前能覆盖它的存活月音狐并准确定位，与狐的施盾可达名单形成双向查看。延续用户「提交并下一步」的自主实施授权，不另加确认轮次，新开发留待下轮提交。

比较仅显示数量、混入准备施盾来源、独立可达来源名单三种方案。本次采用独立默认收起名单：保留冷却/准备和几何范围之间的区别，又能核对每只来源狐。放在已有属性面板内，避免在顶部增加展开项。

## 规则与数据

在shield-coverage.ts增加shieldSources(battle,targetId)只读投影，模型含targetId、alive与sources；每个来源含id、rank、position副本、range。缺战斗/缺目标/备战返回null，目标倒下返回alive=false和空名单。存活目标可为任意种类，含桃和狐；来源必须是存活上阵狐，不要求光环解锁阶数，含本狐自身。

来源的heroRange包含本场射程天赋，整体中心距离不大于射程才可达。与前向shieldCoverage共用局部距离判断，保持两方向一致，不变更引擎shieldTarget。来源按行、列、编号排序，完整Combat/RNG只读，坐标独立。已有盾量/叠盾上限、准备动作/冷却、攻击光环不参与范围资格。

## UI与生命周期

ShieldSources组件接收nullable投影和onSelect，默认收起的「施盾可达来源 · N只」，展开后显示月音狐阶数、编号、坐标和当前射程；自身明确标「自身施盾」。存活无来源给出无覆盖说明；倒下对象不给来源入口。

明确说明：只列当前范围，不表示已准备动作、下次获盾或已有护盾归属。按钮复用BattleStats的onSource→showAlly，清种类/状态筛选、保留排序并聚焦查看灵兽。换实例属性和来源收起；图鉴往返保留展开，普通切页沿现有生命周期重置。复用覆盖列表样式，无新effect、CSS、持久化或依赖。

## 验证与约束

真实Combat全目标/狐逐对核对前后向互逆，并用shieldTarget隔离候选校验；覆盖低阶狐、0编号、自身/桃/其他狐、多格中心精确边界、range天赋、无覆盖/死亡/缺失/备战、满盾/准备/冷却不改变范围、排序和坐标副本。真实stepCombat可生成并释放施盾，准备与范围仍分开。SSR检查默认收起、实例可访问名称、自施盾及空/死亡/null语义。
