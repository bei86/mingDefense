# 锁定压力筛选设计

用户持续授权“提交并下一步”，本轮提交护盾筛选后自主实施。目标是在暂停战场详情中快速找到当前被敌人锁定或未被锁定的存活灵兽。

## 方案

采用现有灵兽状态下拉框增加 targeted / untargeted，复用 battleInspection 的 targetedBy。相比新增独立筛选控件，保留现有交互并减少窄屏高度；暂不做护盾与锁定交叉筛选，也不增加战场标记。

两组选项为“被锁定（存活）”“未被锁定（存活）”。仅按存活与当前投影锁定数 >0 / =0 分组，数量基于当前种类，合计等于该种类存活数。死亡敌人、无目标敌人、无效编号及倒下者不制造压力；备战不参战。冻结或尚在接近的存活敌人仍按现有缓存计算，不重判仇恨。准备普攻与横扫不参与筛选，不承诺下一击，也不宣称未被锁定者安全。

沿用锁定数量降序排序，同值按站位与编号，候选将“锁定 N只”放在名称前，保证320宽关键指标可见。更换筛选保留匹配选中，否则选择当前排序首只；空交集保留控件，无实例和导航。图鉴返回保持条件；快捷定位清种类/状态并保留排序，普通切页恢复默认。

仅改选择投影和展示，不改引擎/规则/数值/RNG、3格接敌、content prototype-2026-10-22-v24/schema2、存档/收藏/备份、素材、依赖与默认命令。

## 验收

真实Combat投影验证分类、种类内计数、编号0、无效缓存、冻结/接近、倒下与备战、缓存转移后重读及只读性；SSR验证控件、指标前置和空态。浏览器独立试玩验证自然非零锁定、排序、图鉴、逐只导航、快捷定位、切页、键盘与320/390尺寸，不读写正式进度。全量测试、构建、启动边界与格式检查通过；不将模拟视口当真机验收。
