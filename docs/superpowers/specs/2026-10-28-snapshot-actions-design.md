# 战场快照当前行动

## 目标与取舍

上一轮快照只有生命、护盾、缓存锁定与横扫，缺少双方当前动作，无法对照为何尚未出手。本轮补充灵兽行动状态/冷却/产钱与准备攻击或施盾，以及敌人普攻状态/冷却/准备目标。延续用户「提交并下一步」的自主实施授权，本人设计、开发、验收，不派代理，新开发留工作区。

比较直接序列化原始队列、另建准备动作算法、复用已有详情投影三种方案。采用battleAction与enemyInspection中的enemy.attack：保持面板与导出一致，既不推测下次攻击，也不把缓存锁定当已准备目标。

## 数据与展示

battleSnapshotDocument沿用原暂停门禁、来源标记、文件名与只读约束。上阵表后增加「灵兽当前行动」，按原站位和编号逐只列来源名称/编号/阶数/锚点、状态、再次行动最早冷却。桃改列独立产钱倒计时，倒下者仅列停止行动，不列旧准备动作。存活非桃按battleAction.pending实际顺序列准备动作，包含攻击/施盾、第几次动作、目标所属阵营/编号、剩余时间；0为待释放，失效目标明示不会生效。

存活敌人表后增加「敌人当前普攻」，沿首领优先/编号顺序列状态、冷却与准备目标；冻结剩余和解冻后冷却/准备分开。目标是当前准备动作的实际目标，可能不同于缓存目标。现有enemyAttack没有动作序号，导出不补造序号。目标存在但倒下时保留名字/编号，无目标记录只保留编号；均明确无效。己方/敌方与编号0合法，不能混淆。

本轮不导出完整已发出攻击/持续效果，不作为下一次命中、伤害、施盾成功或胜负预测。全部时长使用游戏内时间；暂停期间不流逝。导出包含所有实例，不受筛选和页签影响。BattleSnapshot介绍文案补充行动内容，不改TextExport及引擎。

## 验证

先新增测试确认旧快照缺行动章节，再实现。真实stepCombat对照已准备攻击和释放、狐施盾目标与实际护盾增长、桃产钱与倒下停止；双方同号/编号0、重复动作排序、缓存目标与准备目标不同、死亡/缺失目标、冻结/零剩余、空名单、源数组/Session/RNG只读。SSR检查介绍与正文。

全量测试、构建、显式启动边界、格式/diff检查。Chrome独立stage50自然开战暂停，核对动作与面板，验证筛选后的完整导出、切页/档案与关闭重开，尝试320/390实测与截图。上一轮下载事件和剪贴板读回未确认，继续明确边界，不访问被禁止的浏览器内部页或绕过策略。正式页只读核对，清理新建试玩和视口。
