# 小妖卫道原型：补齐数值与执行规则

日期：2026-10-14。

## 1. 本次授权与文档优先级

用户已授权：网上缺失的数值先按经验设计，下次活动开放后通过实机体验校准。此前“未提供生命就不得开工”的限制因此解除。

原型保留已查到的攻击成长、技能质变、15 果刷新、180 秒上限等参考项；缺失参数采用本文临时设计。它是一套可用于开发和试玩的初始配置，不是完整还原结果，也不是经过实战验证的平衡结论。

数值文件：[prototype-balance.json](./2026-10-14-prototype-balance.json)。所有未单独标注来源的值默认为 P；即使技能效果来自攻略，其补齐的持续时间、范围、上限和叠加方式也属于 P。

| 标记 | 含义 |
| --- | --- |
| A | 公告正文或截图明确的数值/机制 |
| B | 第三方攻略记载，尚未实机验证 |
| C | 修复笔误或破损文本的候选值 |
| P | 本次授权后设计的临时参数/规则 |

本文提供首关及第1–5关的基础实施规则和八英雄六阶数值；2026-10-16已扩至第十关，新增敌人/第二首领以[十关设计](./2026-10-16-ten-stages-design.md)为准。与旧总体/英雄设计冲突时，以当前原型执行规则为准。网上资料表仍保持查证记录性质，不把P值写成原作证据。

选择的路线为“保留有来源数据、补齐缺项、先验证五关”。全部重做原创数值会增加后续比对工作；等待原作所有资料则会继续阻塞。50 关曲线在五关实测后另行设计，不把未经试验的外推当作已完成平衡。

## 2. 首期范围

- M1：仅第一关、火云鼠/天蓬猪/御剑鹰、1–3 阶，验证招募、随机格子、布阵、合成、战斗、聚灵石和结算。经验/天赋选择在 M2 开放。
- M2/M3：第 1–5 关，加入招财桃、北冥鱼、仙乐狐，开放六阶、经验天赋、临时 Boss 和本地整备存档。
- 2026-10-16 八灵补齐批次接入齐天猴、熊大师，显示名穿林猿、磐拳熊；M1仍只保留教学三灵，参见[八灵设计](./2026-10-16-eight-beasts-design.md)。
- v8补齐远程/召唤/分裂敌人并开放6–10关、二阶招募和第二首领；第10关才完成当前原型。
- 角色名称用于内部原作对照，发布素材与命名仍按原有原创要求处理。

## 3. 棋盘、招募与合成

### 3.1 棋盘与单位形状（P）

棋盘 6 列 × 6 行，左上为 `(0,0)`，向右、向下递增；单位锚点为形状左上角。初始开放 `x=1..4, y=3..5` 的 12 格，敌人从上方 `y=-1` 入场。上方是前排，下方是后排。

| 英雄 | 形状相对坐标 | 占格 |
| --- | --- | ---: |
| 招财桃、火云鼠、仙乐狐 | `(0,0)` | 1 |
| 天蓬猪 | `(0,0),(1,0)` | 2 |
| 熊大师 | `(0,0),(0,1)` | 2 |
| 北冥鱼 | `(0,0),(0,1),(0,2)` | 3 |
| 齐天猴 | `(0,0),(1,0),(2,0)` | 3 |
| 御剑鹰 | `(0,0),(1,0),(0,1),(1,1)` | 4 |

首期不旋转，不实现自动交换。拖动失败原样返回，保留一次撤销；数值和概率不受撤销影响。英雄升级不改变形状。

格子卡领取后，玩家点选一个与已开放区域边相邻的未开放格；点取消则保留卡，领取其他卡和开战仍允许，刷新前需处理该未领取卡。棋盘最多开放 36 格。

### 3.2 招募经济

- 起始 45 金络果（P）；教学初始免费提供火云鼠两只、猪一只、鹰一只，全部一阶（P）。教学组合只用于保证首关可验证，不声称原作如此开局。
- 刷新一次 15 果（B），展示 3 张卡（P）。领取不额外扣果（P），避免同时引入尚无证据的购买费。
- 每个卡位独立抽取：80% 英雄、20% 战斗格（P）。英雄在当前实现池内等权，可以重复。满 36 格时格子权重归零、英雄权重变为 100%。
- 起始免费英雄也进入招募槽，教学槽容量为 4；其后的常规刷新容量为 3。开战不要求领取全部卡。按用户 2026-10-15 的修正规则，进入下一关整备时免费刷新一轮招募，使用常规英雄/扩地令抽取规则，并覆盖上一关未领取的卡；失败重试或返回布阵保留开战前招募。手动付费刷新须确认放弃剩余卡，当前卡本身不可出售换钱。
- 免费暂存最多 2 个英雄实例（P），不按英雄占格计数；暂存英雄不参战、不产果、不提供光环。后续实机确认免费/付费限制后再改适配规则。
- 棋盘和暂存均满时可在同一命令中领取并合成，或先丢弃已有英雄；丢弃不返果（P），已解锁格子不收回。不允许先扣资源、再因容量失败丢失英雄。
- 同类型同阶两只合成：阶级 +1，保留目标实例 ID 与目标位置，来源实例删除。目标在暂存则继续暂存；最高阶或超出本批次阶级上限时拒绝合成。

| 阶段 | 商店一/二/三阶概率（P） |
| --- | --- |
| 1–5 关 | 100% / 0 / 0 |
| 6–10 关 | 85% / 15% / 0 |
| 11–20 关 | 70% / 25% / 5% |
| 21–50 关 | 50% / 35% / 15% |

前两档已经实现，后两档仍是扩展候选。1–10关基础收入为25/30/35/40/60/45/50/55/60/90果（P）；第5关通关后继续第6关，第10关完成原型。

## 5. 战斗空间、伤害与聚灵石

我方不移动；敌人向目标直线移动。棋盘只约束我方占位，不作为寻路障碍，首期敌人之间也不阻挡。敌方接触距离为目标形状最近占格中心 0.6 格；远程使用 4 格。英雄射程从自身形状中心到敌人中心计算。这些空间规则均 P，可在实机后替换，不依赖动画碰撞。

按用户 2026-10-16 的要求，敌人先清空最前方有存活我方单位的一整排，再推进下一排。每 250ms 重新评估，当前目标死亡则立即重选。多格灵兽按最上方占格归排，整只阵亡才移出该排；空排跳过。同排暂按低阶优先，同阶按类型仇恨从高到低，再按最近占格距离、实例 ID 选目标；不限制附近半径。类型按用户修正为桃 > 狐 > 鼠 > 猪 > 鱼 > 鹰，相对显示值8/7/6/5/2/1；熊4、猴3沿用旧设计预留位，现已接入八灵池。数字为P，不是原作已核实数值。用户未明确等级方向与类型先后，已说明暂按低阶优先的假设；网上攻略仅提供低阶前排的站位建议，详见[仇恨检索记录](../../research/2026-10-16-enemy-threat-and-rank.md)。敌人类型间暂共用此规则。英雄仍优先最近射程内敌人，平局按实例 ID，不加入隐藏的“优先 Boss”规则。

固定步长 50ms；同一逻辑时刻顺序为生成/增益更新、索敌移动、攻击开始、命中事件、死亡/分裂、经验及能量、阶段判断。事件平局按稳定实体 ID、攻击序号和段序排序。前摇结束前施法者重伤则取消；攻击已发出后其后续命中和剑阵独立完成，原目标已死时普通单体命中落空，不重新索敌。攻击序号在行动开始时递增。

- 单位受伤先扣个人护盾，再扣个人生命；不共享伤害池。HUD 总生命是上阵单位当前生命之和，总上限是其最大生命之和，暂存不计入。
- 命中伤害 = 基准 × 技能倍率 × `(1+通用攻击加成+单位加成+光环加成)` × `(1+易伤)` × `(1-减伤)`，最后向下取整，最少 1。鼠残血增伤作为技能倍率；鹰剑阵额外增伤单独乘 `(1+剑阵加成)`。
- 狐护盾 = 目标最大生命 ×3%×`(1+护盾天赋加成)`，最后向下取整，达到护盾上限后停止增加；8% 天赋是乘数，不是增加 8 个最大生命百分点。
- 攻速加成为加法，总额最多 +200%；攻击开始间隔为 `ceil(基础间隔/(1+攻速加成)/50)*50ms`。前摇也按相同攻速换算并向上取整到 50ms，至少一个步长。
- 聚灵石容量 100、起始 0、普通击杀 +5（P）；长按每模拟秒耗 20，所有上阵单位攻速 +50%（P）。每步耗 1，能量不足时本步不生效；玩家松手、暂停、页面后台或打开天赋界面均清除按住状态，恢复时需重新按。
- 聚灵石增攻速影响狐的行动，不影响桃产果、场上剑阵计时、敌人攻速或关卡倒计时。Boss 击杀不充能；召唤小怪不提供经验/能量，分裂小怪按其单独配置，避免无限养经济/经验。

### 临时首个 Boss（全部 P）

v3（2026-10-16）生命 72000、普攻伤害 55、间隔 1500ms、移速 0.35 格/秒、射程 0.8 格，击杀经验 30，从中间列入场。每 12 秒对当前最前排存活英雄所在行发动横扫，预警 1200ms，命中该行所有存活英雄各 75 伤害，不以普通普攻倍率放大。v2的24000/45/60已保存在2026-10-15-prototype-balance-v2-snapshot.json；三项均为P，调整依据见2026-10-16战报与平衡验收。

生命 ≤40% 后普攻攻速 +25%，立即召 2 只小怪，之后每 20 秒再召 2 只，最多同时 6 只。Boss 重伤/死亡后取消尚未生成的召唤与横扫；已经生成的小怪仍须清完。它用于验证 Boss 状态机和反馈，不声称是原作第 5 关的实际 Boss。

首关预期战斗观察区间为 45–75 秒；Boss 为 30–90 秒；它们是试玩观察目标，不能据静态表宣称已经达到。完整五关闭环需单独统计战斗、整备、天赋和重试时间，不沿用旧“整轮 5–8 分钟”承诺。

## 7. 经验与天赋

下一等级所需经验依次 60/80/100/120/150/180/210/240/280/320，之后每级增加 40（P）。扣除当前阈值后保留多余经验，连续升级依次排队选择，级别从 1 开始。

击杀结算后立即暂停并打开三选一；选择结束恢复同一逻辑时刻。胜负条件同帧也成立时优先完成战斗结果，胜利后再处理待选天赋，失败丢弃关内经验。打开选择时清除聚灵石长按。

候选先过滤：当前未达上限、对应英雄已上阵、前置条件满足；鹰剑阵强化另要求已有三阶鹰。每次从剩余项按普通/稀有/史诗 70/25/5 权重不放回抽取；品质为空时移除其权重并归一化。少于三项则显示实际数量，不给无效项；没有可升级项时本次等级改奖励 5 果，亦随关内增量结算。

## 8. 关间恢复、退出、随机与存档

- 普通关胜利：确认一次性结果 → 结算果子/经验等关内增量 → 处理排队天赋 → 恢复全员生命、清空护盾和临时状态 → 下一关整备并免费刷新三张招募。永久天赋、单位、位置及解锁格保留。每次有效推进关卡只刷新一次，刷新整备页面不再次抽取。
- 每次按开战按钮前保存完整整备检查点，包括所有随机流、果子、商店卡/领取状态、经验、单位、解锁格、待选天赋与日志游标。失败或主动退出本关恢复此检查点，关内产果、经验和天赋不保留。
- 原型免费不限次数重试（P），使用同一检查点随机状态；调整阵容/刷新会产生新的合法输入，但重复进入同一战斗不刷新商店结果。
- 商店、天赋、战斗使用独立可复现随机流。验收条件为相同内容版本、初始状态和带逻辑时刻的输入下，1/2 倍速结果一致，不能只比较种子。
- 本地保存阶段为整备、关后天赋和完成；中途刷新/异常关闭回到最新检查点。存档只含规则状态，不保存渲染对象。
- 版本字段采用 JSON 的 `contentVersion`，校准时升级版本、保留旧数值快照；规则含义不变时只替换配置。棋盘/技能等语义变化另改规则层，不能承诺所有校准都只改数值。
- 原型旧档内容版本不兼容时保留原档备份并提示开始新局，不静默套用新参数，正式档迁移另行实现。
- v8对已知v2/v3/v4/v5/v6/v7提供定向迁移：先校验、备份，再保留当前整备/已结束战斗及奖励；未知版本仍按不兼容处理。旧第五关完成档可继续第六关。逐兽战报为可选增量，旧胜利记录不伪造统计。各批修改前配置保存在对应版本快照中，十关扩展前为v7快照。

## 9. 设计校验与试玩验收

配置静态检查：八英雄每条生命/伤害为六项，生命为正整数；形状不重复、占格合法；各概率和为 100；间隔为 50ms 整数倍；单位和召唤引用存在；第一关包含完整三波；首期范围与技能开放一致。

开工顺序：M0 竖屏框架和生命周期 → M1 三英雄首关闭环 → M2 连续成长与天赋 → M3 Boss、本地恢复和五关试玩。数值文件放在设计目录，实施时由内容模块按版本加载并以 Schema 校验，不能让 UI 直接修改规则状态。

M1 验收以真实手机完整操作和确定性回归为主；M3 增加至少三种阵容的比较及弱势场景。需要观察：伤害/承伤来源、首关失败原因、合成带来的取舍、剩余果子与刷新次数、格子不足次数、聚灵石使用时机、各关完成时间。首轮不能保证通关率或全部流派有效。

下次原作活动开放后的优先校准：首关初始条件与格子形状 → 生命/攻速/射程 → 聚灵石与天赋 → 敌人及 Boss → 恢复/退出 → 长局成长。对每项留下原型值、实测值、录像时间点和差异原因，验证后才把 P/C 改为已核实来源。
