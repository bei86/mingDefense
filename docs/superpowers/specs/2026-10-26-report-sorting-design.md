# 逐兽战报多维排序设计

用户持续授权“提交并下一步”，本轮先提交敌人普攻查看，再自主完成结算复盘改进。

## 目标与取舍

当前结算逐兽表只按伤害排列，难以找到承伤、施盾、护盾吸收和产钱贡献者。采用表上原生下拉框切换五种指标，统一降序，同值按实例编号升序。相比同时增加五列，这保留窄屏四列表；相比新增排行榜，不重复已有战报数据。

## 行为与边界

- 默认仍按伤害排序，保留生命状态、位置、原四列与阵型复盘、重伤时间线。
- 提供护盾与护盾吸收分别排序，每行显示两项原始记录，0与未记录明确区分；每只灵兽显示编号以区分同名实例。
- 缺失指标排在所有已记录值（含0）之后，并显示“未记录”；不补算、不折算为0。
- 表格标题明确当前降序依据，下拉有可访问名称、至少44px高，窄屏不新增列。用户展开战报后才看到工具。
- 排序仅改变界面顺序，不写入Combat、战役、战报收藏或导出文本；收起再展开保留当次选择，离开结算后无需保存偏好。
- 不修改模拟/数值、RNG、schema2/contentv24、3格接敌、依赖、素材或原npm命令。

## 结构与验证

`report-unit-sort.ts`负责指标元数据、缺失读取与无副作用排序；`ReportUnits.tsx`负责选择和原有逐兽表；`BattleReport`保留整体复盘结构。纯函数测试覆盖五种排序、同值/0/缺失、输入不变；真实战斗核对排序不影响存档与导出，SSR核对各模式数值和旧记录。真实隔离试玩完成一关，检查五种切换、折叠、结算操作、390/320宽和控制台。

自审：指标口径来自既有战报，施盾不等于实际吸收，承伤不含护盾；没有新增胜负推断或未知参数。范围为单项结算呈现改进。
