# 冻结首领的预警时间说明

上一轮已提交e70c1b9。用户持续授权自主下一步；本轮顺序实施、自审和验收，不派代理，新开发留工作区。

## 问题与选择

HUD已在首领冻结时提示释放延后，敌人详情的横扫/回响仍只显示“剩余X秒”或“待释放”。采用详情内分开显示冻结剩余与解冻后准备时间，避免误解为当前倒计时仍在流逝。相比只加统一免责声明，这能对应每个首领当前状态；不累计成预计命中时间，因为后续冻结与目标存活可能变化。

## 规则与展示

InspectedWarning新增必需frozenMs。只对boss来源按max(0,frozenUntil-battle.time)计算，其他来源为0，匹配引擎只有首领冻结才顺延横扫due的逻辑。原remainingMs仍为max(0,due-time)。所有值只读；不改变排序、行号、回响、行内名单及快捷定位。

冻结且准备剩余大于0：显示“解冻后准备 X 秒”，另显示“冻结剩余 X 秒 · 释放延后”。冻结且准备0：显示“待解冻”，不能显示待释放。未冻结保持原有剩余/待释放。冻结刚到期不再标冻结。为冻结条目说明准备时间解冻后继续，不将冻结时间与准备时间相加承诺命中。

## 验证

真实Combat生成横扫与回响，再冻结多tick验证准备剩余保持、冻结剩余下降、解冻后计时恢复并实际释放；零准备、1ms与到期边界、同名不同来源、死亡/退场及普通来源隔离、SSR和只读覆盖。浏览器隔离自然第50关捕获预警，核对普通/冻结实际能观察到的状态、快捷定位与390/320；冻结捕获若不稳定由真实Combat测试承担并明确边界。
