# 小妖卫道玩法复刻项目设计

日期：2026-08-10

## 1. 项目目标

开发一款面向手机浏览器的原创竖屏 H5 游戏。玩法与《寻道大千》的活动小游戏“小妖卫道”保持高度一致，保留布阵、随机商店、同名合成、自动战斗、局内 Buff、每五关 Boss 和长局成长等核心机制。

项目不使用原作名称、角色形象、界面、美术、音效或其他受保护素材。角色命名、世界观、视觉表现和音频全部原创。

最终目标是活动级在线产品，但采用纵向切片方式推进：

1. 第 1 关验证布阵、购买、合成和自动战斗闭环。
2. 第 2 至 5 关验证连续成长、Buff 和首个 Boss。
3. 扩展为每五关一个 Boss 的 50 关长局。
4. 完成单位、敌人、Boss、Buff 和原创素材。
5. 最后接入游客账号、正式账号、云存档、排行榜和防作弊。

## 2. 已确认的原作玩法

根据公开攻略资料，原作包含以下规则：

- 商店消耗金络果刷新单位，每波胜利及招财单位可产出资源。
- 单位放置在格子战场中，不同单位占用 1 至 4 个格子。
- 两个相同单位可以合成为更高阶单位，最高约 6 阶。
- 战斗自动进行，击杀敌人获得经验，升级后选择强化 Buff。
- 每关倒计时约 180 秒，超时或我方全部重伤即失败。
- 普通关用于发育，每 5 关为 Boss 关。
- 低阶、小体积单位可在前排承伤和拉扯，高阶输出及保护单位放在后排。
- 主要目标为 50 关，公开资料称最多可继续到 99 关。
- 原作提供 1 倍速和 2 倍速。

公开资料没有完整说明棋盘精确尺寸、重伤跨关恢复规则及所有数值。这些内容不得凭推测锁死，应在拿到清晰实机录像后通过配置校准。

参考资料：

- https://www.9game.cn/news/11052870.html
- https://www.9game.cn/xddq/11027621.html

## 3. 产品范围

### 3.1 目标平台

- 首发平台为手机浏览器 H5。
- 竖屏优先，设计基准为 390 x 844。
- 最小支持宽度为 320px。
- 桌面浏览器显示居中的竖屏游戏区域，不改造成横屏玩法。
- 微信小游戏不属于首版范围，但平台相关能力应通过适配器隔离。

### 3.2 单轮时长

- 第 1 至 5 关构成一个 Boss 循环。
- 每轮目标时长为 5 至 8 分钟。
- 完整 50 关预计 1 倍速耗时 50 至 80 分钟，2 倍速耗时 30 至 45 分钟。
- 首版提供 1 倍速和 2 倍速；模拟稳定后增加 3 倍速和 4 倍速。

### 3.3 非目标

首个可玩版本不包含：

- 正式美术全集。
- 账号注册和登录。
- 云存档。
- 排行榜和赛季。
- 支付、广告和商业化。
- 微信小游戏适配。
- PvP 或实时联机。

## 5. 第 1 关闭环

### 5.1 流程

第 1 关流程为：

`进入关卡 -> 商店刷新 -> 购买单位 -> 拖入棋盘 -> 调整或合成 -> 开战 -> 自动战斗 -> 胜利结算`

战斗开始后锁定购买和布阵，只允许暂停、继续、倍速切换、查看信息和退出本局。

### 5.2 我方单位参考与首批范围

完整英雄名单、六阶属性和技能节点见 [我方英雄与升阶设计](./2026-08-11-player-heroes-design.md)。

M1 只实现三个玩法代表：单格火云鼠、双格天蓬猪和四格御剑鹰，分别验证单体攻击、多格占位与范围伤害。敌方只提供一种基础近战怪。第 1 关包含三个短波次，目标时长为 60 至 90 秒。

### 5.3 棋盘与合成

- 棋盘行列数通过配置定义。
- 单位形状由相对格坐标集合定义。
- 拖动期间显示合法、冲突和越界状态。
- 非法放置不会修改模型，单位返回原位置。
- 同类型、同阶单位可以合成。
- 合成保留目标位置并提升一阶。
- 若升级后的形状不能合法放置，则拒绝合成。
- 第 1 关开放 1 至 3 阶，完整版本最高 6 阶。

### 5.4 商店与随机性

- 商店一次展示固定数量的随机单位。
- 购买后单位进入待部署区。
- 刷新基准消耗暂按原作公开资料中的 15 金络果配置。
- 第 1 关测试模式使用固定随机种子，稳定提供可合成组合。
- 正式模式由一局的种子驱动商店、Buff 和战斗随机行为。

### 5.5 战斗规则

模拟器使用固定时间步长，顺序为：

`索敌 -> 移动或转向 -> 攻击前摇 -> 命中结算 -> 冷却`

投射物、动画、粒子和伤害数字只负责表现，不作为伤害判定依据。倍速改变模拟时间推进速度，不跳过规则步骤。我方全灭或倒计时结束时失败，敌人全部消灭时胜利。

### 5.6 第 1 关验收

- 玩家能够完成购买、布阵、合成、开战和结算。
- 多格单位不会重叠或越界。
- 玩家至少能完成一次二合一升阶。
- 同一随机种子产生相同商店序列和战斗结果。
- 1 倍速和 2 倍速的最终结果一致。
- 页面进入后台后暂停，返回时不会发生时间跳跃。
- 连续自动运行 20 局无卡死、重复结算和状态残留。

## 6. 第 2 至 5 关

### 6.1 关卡节奏

| 关卡 | 目标时长 | 新机制 | 目的 |
| --- | --- | --- | --- |
| 1 | 60 至 90 秒 | 基础近战怪 | 验证核心闭环 |
| 2 | 60 至 75 秒 | 成群小怪 | 验证范围输出 |
| 3 | 60 至 75 秒 | 高速敌人 | 验证站位和集火 |
| 4 | 75 至 90 秒 | 肉盾和混合波次 | 验证持续输出 |
| 5 | 90 至 120 秒 | 首个 Boss | 验证完整构筑 |

每关保留 180 秒硬上限。

### 6.2 关间整备

普通关胜利后发放金络果，保留单位、阶级和位置，恢复生命并清除临时战斗状态。达到升级条件时先进行三选一 Buff，再进入商店和布阵阶段。玩家主动开始下一关。

首版将重伤定义为本关无法继续战斗，下一关恢复。该规则属于实机校准项，获得可靠资料后只修改配置和阶段处理，不改变存档格式。

### 6.3 Buff 系统

初版实现三类共 12 个 Buff：

- 通用属性：攻击、攻速、生命和射程。
- 职业强化：单体穿透、范围扩大和战士减伤。
- 经济成长：关后额外果子、刷新折扣和高阶单位概率。

Buff 分为普通、稀有和史诗品质。普通 Buff 默认最高 3 级，满足组合条件后解锁更高品质的组合强化。第 1 至 5 关使用受限 Buff 池，避免出现对当前阵容完全无效的选择。

### 6.4 普通敌人

- 群行者：数量多、生命低。
- 疾行者：移动快、生命低。
- 岩甲兽：生命和减伤高。
- 第 4 关使用岩甲兽搭配群行者的混合波次。

### 6.5 首个 Boss

首个原创 Boss 定位为阵型破坏者：

- 第一阶段使用基础近战攻击。
- 第二阶段周期性冲击最前排直线，并提供清晰预警。
- 生命低于 40% 后召唤小怪并提高攻击速度。

玩家可用前排承伤、主输出避开冲击路径、范围单位处理召唤物。Boss 不使用无预警秒杀技能。

### 6.6 失败重试

- 失败后回到本关整备阶段。
- 恢复进入该关前的阵容、资源和 Buff 检查点。
- 允许调整站位、刷新或合成后重试。
- 首轮免费重试。
- 重试恢复相同随机状态，不能通过反复进入刷新结果。

## 7. 多轮 Boss 与 50 关成长

### 7.1 长局结构

每五关由四个普通关和一个 Boss 关组成。内容按以下节奏展开：

| 关卡 | 主要变化 |
| --- | --- |
| 1 至 5 | 教学循环，建立基础阵容 |
| 6 至 10 | 远程敌人与控制需求 |
| 11 至 15 | 死亡分裂和召唤敌人 |
| 16 至 20 | 首次出现敌人词缀 |
| 21 至 30 | 双词缀、混合波次和阵型克制 |
| 31 至 40 | Boss 技能组合和精英敌人 |
| 41 至 50 | 高压构筑检查和最终 Boss |

### 7.2 Boss 与词缀

首版规划五个基础 Boss：

1. 阵型破坏者，冲击直线。
2. 召唤统领，持续召唤小怪。
3. 远程首领，攻击后排。
4. 分裂巨兽，阶段性分裂。
5. 最终首领，组合前四类机制但降低单项强度。

第 30 至 50 关复用基础 Boss 并增加狂暴、坚甲、迅捷、召集或再生词缀。每个 Boss 最多携带两个词缀。

### 7.3 数值成长

敌人最终属性由基础属性、关卡成长、精英或 Boss 系数和词缀修正共同计算。生命成长快于攻击成长，普通关主要增加组合和数量，Boss 关主要增加机制压力。每五关形成明显台阶，40 关后由指数式增长逐步转为线性增幅，避免数值失控。

玩家通过四条线成长：

- 单位合成至最高 6 阶。
- Buff 升级及组合强化。
- 解锁棋盘容量或备战位。
- 提升商店高阶单位出现概率。

10 关前形成主力，20 关前确定流派，30 关前形成核心组合，40 关后优化阶级、站位和次要 Buff。

### 7.4 经济和平衡

- 金络果同时承担购买和刷新成本。
- 普通关提供稳定收入，招财单位提供额外收入和阵容机会成本。
- Boss 关提供阶段奖励。
- 商店概率随循环提升，降低后期低阶无效操作。
- 出售单位返还部分资源。
- 至少支持范围清场、单体爆发和控制保护三条有效流派。
- 正常构筑首轮首次通关率目标约 70%。

### 7.5 高倍速

3 倍速和 4 倍速在模拟器确定性验证完成后开放。高倍速降低非关键粒子、动画和伤害数字刷新频率，但不跳过模拟步骤。Boss 首次遭遇只开放 1 倍速和 2 倍速，击败后才开放更高倍速。

### 7.6 长局验收

- 可以从第 1 关连续运行到第 50 关。
- 每五关的难度和机制有明确变化。
- 三种主要流派均可通关且各有弱势关卡。
- 第 40 至 50 关不依赖某个唯一随机 Buff。
- 1 至 4 倍速在固定输入下结算一致。
- 自动模拟至少覆盖一万局策略组合。
- 长时间运行不存在持续内存增长。

## 8. 前端技术架构

### 8.1 技术栈

- Vite、TypeScript。
- Phaser 3 负责战场、动画、特效和触摸输入。
- React 负责商店、Buff、菜单、登录和排行榜界面。
- Zustand 管理界面和会话状态。
- Zod 校验配置和存档。
- Vitest 执行单元测试。
- Playwright 执行手机端流程测试。

### 8.2 模块

```text
src/
  app/             启动、路由、依赖组装
  session/         单局流程、状态机和命令
  simulation/      实体、索敌、移动、攻击和伤害
  board/           棋盘、形状、放置和合成
  economy/         商店、购买、出售和奖励
  progression/     经验、Buff、组合和难度
  content/         单位、敌人、Boss 和关卡配置
  renderer/        Phaser 场景、动画、特效和音频
  ui/              React HUD、商店和弹窗
  persistence/     本地与云端存档适配器
  platform/        H5 生命周期和触摸适配
  telemetry/       调试指标及后续埋点
```

React 和 Phaser 均不直接修改模拟状态，只通过会话命令层提交操作。模拟器产生事件流，渲染层消费事件并播放表现。

### 8.3 状态机

```text
BOOT -> HOME -> PREPARE -> COMBAT -> VICTORY/DEFEAT
     -> BUFF_SELECT -> PREPARE -> RUN_COMPLETE
```

每个阶段维护允许命令列表。战斗阶段拒绝购买、移动和合成，避免界面与规则状态竞争。

### 8.4 配置

配置对象包括 `UnitDefinition`、`EnemyDefinition`、`StageDefinition`、`BuffDefinition`、`ShopDefinition` 和 `DifficultyDefinition`。启动时统一校验引用、形状、概率、曲线和关卡生成条件。配置错误在开发模式显示具体路径，在生产模式阻止使用错误内容开始新局。

## 9. 存档、随机性和回放

### 9.1 存档边界

存档只记录可序列化规则状态，不记录 Phaser 对象、动画或计时器。核心字段包括：

```ts
interface RunSave {
  schemaVersion: number
  contentVersion: string
  runId: string
  seed: string
  stage: number
  phase: "prepare" | "buff-select" | "complete"
  currency: number
  experience: number
  playerLevel: number
  units: SavedUnit[]
  buffs: SavedBuff[]
  board: SavedPlacement[]
  shopState: SavedRandomState
  statistics: RunStatistics
  updatedAt: string
}
```

- 只在整备、Buff 选择和完成阶段保存。
- 每关开始前创建检查点。
- 页面异常关闭后恢复到最近整备阶段。
- 存档带 Schema 和内容版本，并通过迁移函数升级。
- 本地和云端存档实现共享接口。

### 9.2 确定性记录

每局记录初始种子、商店刷新、Buff 选择、购买、出售、合成、站位命令、关卡阵容快照和结果摘要。这些信息用于问题重现、自动平衡、回放及后续服务端成绩验证。

## 10. 后端能力

后端技术栈在 M6 开始前确定。当前通过 OpenAPI、版本化规则协议和黄金测试向量保持实现无关。

### 10.1 接入顺序

1. 本地游客模式。
2. 服务端游客身份。
3. 云存档。
4. 正式账号绑定。
5. 赛季排行榜和成绩验证。

### 10.2 账号

身份包括本地游客、云端游客、正式账号和禁止排行账号。游客升级正式账号时保留长局、历史最高关卡、图鉴、设置、成就和排名记录。邮箱、手机号或第三方登录由独立认证适配器实现。

### 10.3 云存档

云存档使用递增修订号和乐观并发控制。客户端提交的修订号与服务端一致时才接受更新，否则返回冲突。冲突界面显示两份存档的关卡、时间和设备来源，由玩家选择；奖励领取记录以服务端为准，不允许回滚。

### 10.4 核心接口

```text
POST /auth/guest
POST /auth/register
POST /auth/login
POST /auth/bind
GET  /profile
GET  /save/current
PUT  /save/current
POST /save/resolve-conflict
POST /runs
POST /runs/{runId}/checkpoints
POST /runs/{runId}/complete
GET  /runs/{runId}
GET  /leaderboards/{season}
GET  /leaderboards/{season}/me
```

所有写操作携带幂等键。

### 10.5 排行榜

排行优先级为：到达关卡、到达时间、验证状态。已验证成绩优先，验证失败的成绩不进入公开榜。后续可增加最高关卡、最短用时、无付费增益和每周特殊规则榜。

成绩提交包括 `runId`、种子、规则版本、阵容快照、玩家命令、结果摘要、时间戳及命令日志哈希链。成绩先进入待验证状态，通过后才公开。

### 10.6 防作弊

- 校验资源收入和消费守恒。
- 校验单位来源、阶级、合成次数和 Buff 数量。
- 校验关卡顺序、耗时和客户端版本。
- 根据种子和命令重新模拟关键关卡。
- 普通成绩抽样验证，Boss 和高排名成绩完整验证。
- 可疑成绩进入隔离队列并保留审计记录。

后端若无法直接复用 TypeScript 模拟器，必须通过同一组黄金输入输出测试保证跨语言实现一致。

## 11. 错误处理

- 配置错误在启动阶段报告，不带错进入战斗。
- 非法命令由会话层拒绝，并向界面返回原因。
- 本地存档损坏时保留原文件并尝试上一检查点。
- 页面进入后台时自动暂停。
- 非关键素材失败时使用占位素材，关键配置失败才阻止启动。
- 结算通过幂等标识确保只执行一次。
- 网络不可用时继续单机，但不能提交实时排名。
- 云端验证不可用时成绩保持待验证，不丢弃记录。

## 12. 测试策略

每个里程碑必须通过：

- TypeScript 类型检查。
- 单元测试。
- 配置完整性测试。
- 固定种子回归测试。
- H5 生产构建。
- Playwright 主流程测试。
- 320px、390px 竖屏和桌面预览检查。
- 页面后台、刷新和异常恢复测试。
- 上一版本存档兼容测试。

专项测试包括：

- 棋盘旋转、越界、冲突、移动和合成。
- 索敌、攻击间隔、伤害、死亡和胜负。
- 不同倍速下确定性一致。
- 存档序列化、恢复和迁移。
- 同屏 50 个敌人的首版性能及 150 个敌人的压力测试。
- M1 连续 20 局、M3 连续 100 局、M4 至少一万局批量模拟。

## 15. 主要风险

- 原作资料不完整：维护实机校准清单，规则配置化。
- 高倍速结果漂移：固定时间步长、种子和黄金回放测试。
- 小屏多格拖拽困难：扩大命中区、吸附并支持撤销。
- 后期数值失控：批量模拟结合真人试玩。
- 排行榜作弊：命令日志、资源守恒和服务端重演。
- 美术阻塞玩法：第 1 至 5 关使用统一原创占位素材。
- 版本升级破坏旧档：规则版本、内容版本和存档迁移分别管理。
