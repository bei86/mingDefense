# 固定敌袭结束后的收尾提示

## 目标与方案

当前“已出”只统计固定队列，击退数还包含召唤与分裂；两者不能用来判断胜利。选择在波次栏下方增加一条只读状态，沿用深绿底、薄荷文字和现有字体，允许窄屏换行，不覆盖棋盘。

相比新增完整敌人计数面板，这一方案只在收尾时出现；相比弹窗提醒，不打断守卫或聚灵。用户已持续授权“提交并下一步”，本轮直接完成设计、实现与验收。

## 状态与边界

- 固定队列未消费完：隐藏，以 spawnIndex 与 spawns.length 判断，不用时间或击退数代替。
- 固定队列已消费完且存在 hp>0 的敌人：“固定敌袭已出完 · 场上 N 只”。包含召唤、分裂与首领，死亡实例不计数。
- 无活敌，但 attacks / released / fields / warnings 任一非空：“固定敌袭已出完 · 招式结算中”。
- 无活敌及上述招式但尚未判定结果：“固定敌袭已出完 · 等待战果判定”。死亡实例待清理也归此状态，不提前宣告胜利。
- 无战斗、battle.result 已结束，或 Session 不在 combat：隐藏。暂停和待选天赋保留当前只读状态。

状态直接派生，不引入额外时钟、effect、缓存或战斗状态。场上数量不使用 aria-live，避免每次击退打断读屏。现有暂停详情继续解释固定出怪结束后仍可能有召唤、分裂。

## 约束与验收

保持规则、数值、RNG、3格接敌、content prototype-2026-10-22-v24/schema2、存档/收藏/备份格式与容量、素材、依赖和默认命令。

测试实际队列游标、衍生怪与死亡实体、四类残留招式、胜败隐藏、只读暂停及真实 stepCombat 收尾生命周期；SSR检查 CombatStatus 接线和阶段门槛。第50关隔离自然试玩核对固定队列出完后的清敌、暂停、最终胜利隐藏，390/320视口截图检查，保留正式档。
