# 灵兽准备施盾来源

上一轮已提交976e2c0。用户持续授权“提交并下一步”，本轮自行实施、自审、验收，不派代理，新开发留工作区。

## 设计选择

现有狐行动状态可查看施盾目标，目标灵兽尚无反向入口。采用默认收起的“正准备为此灵兽施盾”名单，逐动作显示来源狐阶数、编号、起始站位、动作次数与准备剩余。点击复用现有灵兽定位，清除种类/状态筛选、保留排序、聚焦“查看灵兽”。可从狐当前行动状态返回准确目标。换灵兽收起；图鉴挂起返回保留。

相比把所有范围内狐列为来源，本功能只读真实准备队列，不预测下次施盾；相比追踪已有护盾的历史来源，不新增战斗状态或存档字段。名单按due、来源编号、ordinal稳定排列，保留同名狐、多次动作及自施盾。只包含活着的上阵目标和存活月音狐的己方准备动作；不含普通攻击、敌方动作、桃、已释放效果、倒下/退场对象或备战。双方编号相同按阵营区分，编号0有效。

准备剩余取max(0,due-time)，1ms显示0.1秒，0显示待释放。只展示时间和来源，不计算预计盾量；已有护盾、光环不是准备来源。说明准备不保证获盾，实际增加量由释放时规则决定。

## 验证与边界

真实Combat产生施盾准备，时间推进后消失且目标护盾/施盾战报增加；验证目标改变、同名多狐、自施盾、0编号、排序与独立快照、失效来源/目标、无准备时空说明、SSR接入默认收起和只读Session。浏览器自然捕获施盾准备，核对双向定位、图鉴往返、筛选/排序与焦点、390/320截图和键盘操作。

保持引擎/规则/数值/RNG、3格接敌、content prototype-2026-10-22-v24/schema2、存档/收藏/备份格式容量、素材、依赖及默认命令。

自审：目标按队列而非护盾比例或距离猜测，0与同号阵营明确，接口和生命周期复用现有实现，无待定项。
