# 选择与结算查看天赋手札

用户持续授权“提交并下一步”，本轮先提交上一轮，再按现有流程自主执行，不重复审批。采用 brainstorming 梳理范围与 writing-plans 落地。

## 方案与取舍

推荐复用现有手札，在天赋选择与结算增加明确入口，顶层展示，收起返回来源。只加结算入口不能帮助选择搭配；另做一套选择页图鉴会重复已有13项说明。复用方案覆盖两个缺口，保持现有交互结构。

## 行为

- 天赋选择页新增“查看天赋手札”，进入后默认已获得，可切全部天赋；收起按钮显示“返回天赋选择”。候选、剩余次数、时间和随机状态保持。
- 胜利、失败、五十关完成及开发单关结算均提供“天赋手札”，收起显示“返回本关结算”。结算统计、收益与推进操作保留。
- 失败查看的是结束时本场成长，明确“本关失败，重试或返回布阵后，本关成长会回滚”，避免误认为永久保留。
- 原整备及暂停入口维持默认“收起手札”。顶部关闭按钮保持明确无障碍名称，长列表内部滚动。

## 边界与验证

仅修改 CampaignPanels、BuffJournal 与 App 接线，不引入新状态或依赖。手札继续读取同一个 Session，不调用 pause/chooseBuff/nextStage/retry。保持规则、随机、3格、content v24/schema2、存档/收藏格式与容量、素材和 npm 命令。

用 SSR 检查各类来源与败局说明，以浏览器检查实际点击返回、待选项、正式结算保留、窄屏与键盘焦点。实际手机和原作数值不在本轮验证范围。
